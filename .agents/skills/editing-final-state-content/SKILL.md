# Editing Final-State Content

本 skill 是可复用工作流。仓库真相仍在根/局部 `AGENTS.md`、`contracts/` 及其引用的正式文档中。

## 适用场景

- 任务会修改 `docs/`、`AGENTS.md`、README、代码注释、错误文案、按钮标签、空态文案、提示文案或其他用户可见文本
- 你准备解释界面行为、接口消费顺序、内部实现顺序、数据流或设计用意，需要按文档职责判断哪些属于正式事实
- 你不确定一段文字是否泄露了编辑过程、实现过程或阶段性口径

## 工作流

1. 只写最终态成稿，让文本看起来从一开始就是当前版本。
2. 保留读者完成当前任务或理解该文档正式职责所需的事实、约束、操作和结果；架构文档、事件模型和 implementation order 保留其 owner、数据流、边界与依赖顺序。
3. 删除编辑痕迹、无关迁移叙事、阶段标签，以及不属于当前文档职责的过程或设计说明。
4. 提交前逐段重读，确认每句话都服务于读者当前要看到的最终内容。

## 保留

- 稳定事实：能力、限制、参数、路径、前置条件、结果
- 正式架构 owner、跨层数据流、状态迁移和长期实施顺序
- 对读者有直接作用的操作说明
- 为避免误用或歧义而必须保留的最小技术事实

## 删除

- 编辑痕迹：`不再`、`已改为`、`已移到`、`前后对比`、`不会再`、`这里改成`、`原来`、`之前`、`现改为`
- 开发态标签：`阶段1`、`第一步`、`phase 1` 等阶段或步骤叙事，除非当前文档本身就是变更记录、迁移说明或发布说明
- 不属于文档职责且不影响正确理解的设计说明、技术说明、用意说明
- 通过“先……再……”复述编辑过程的句子；架构数据流、协议顺序、恢复步骤和正式 implementation order 不属于此类编辑痕迹
- 翻译腔与抽象填充词（`裁决`、`承载`、`面`、`投影`、`冻结`、`回落`、`主链` 等）在非正式术语位置的使用

## 改写方向

- 把“如何改过来的”改成“现在是什么”
- 在用户文档中把无关内部串联改成读者行为；在架构文档中保留必要的正式串联与 owner
- 把“作者为什么这样设计”改成“读者必须知道的约束”

## 清理翻译腔与抽象表述

- 把直译回填词换成中文常用说法：`裁决`→`以…为准 / 由…决定`、`承载`→`说明 / 记录 / 存放`、`面`→`接口 / 文档 / 能力`、`投影`→`视图 / 展示`、`冻结 / 未冻结`→`固定 / 已发布 / 尚未发布`、`回落`→`兜底`、`主链`→`正式流程`、`不获得宿主样式`→`不继承宿主样式`。
- 只有 contract 正式名称或产品既有术语才保留；非正式用法的直译词一律清理。
- 一个动词只配一个主语，抽象名词串先拆成要点列表再润色。
- 删除抽象粘连动词（`赋能 / 沉淀 / 闭环 / 驱动 / 组合 / 承接`），换成说明实际动作的动词或直接删。
- 压缩 `只 / 仅 / 必须 / 统一 / 正式` 的防御叠加，只保留真正表达约束的那个。
- 每句话都应能回答“谁做了什么、结果是什么”；回答不了就改写结构。

## 警示信号

- 句子在解释修改过程，而不是交付内容
- 句子解释的内部顺序既不属于文档职责，也不影响正确实现或使用
- 句子删掉之后，读者依然能正确使用内容
- 句子读起来像评审说明、设计说明、提交说明或口头补充

## 反例

- `列表先读 HTTP，再吃 \`/ws/tasks\` 增量更新。`
- `先回放 \`/api/logs\`，再接 \`/ws/logs\` 追加。`
- `这里改成统一入口。`
- `之前使用旧字段。`
- `平台统一裁决生命周期与 artifact 完整性。` → `平台管理插件生命周期，并校验 artifact 完整性。`
- `Web 与 Launcher 只持有临时投影。` → `Web 与 Launcher 只保存临时视图。`
- `本目录承载部署说明。` → `本目录说明部署。`

## 最终检查

- 扫描禁用措辞与阶段词
- 扫描翻译腔与抽象填充词（裁决 / 承载 / 面 / 投影 / 冻结 / 回落 / 主链 等），确认每个抽象名词都有具体所指
- 逐段删除对最终读者没有直接价值的解释
- 仅在 changelog、migration guide、release notes 中保留变更叙事

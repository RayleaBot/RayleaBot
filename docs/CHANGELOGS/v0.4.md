# v0.4 Changelog

RayleaBot v0.4 已交付的能力清单与边界。本文件作为历史基线归档。前置基线见 [v0.3.md](./v0.3.md)。

## 主线交付

- 插件体系一次性破坏性升级：manifest v3、协议 v2、artifact v2、catalog v2、开发工作区 v2、管理桥接 v3、备份 manifest v3 与 CLI contract v2 同步上线，不保留旧合同兼容层或插件包转换器。
- 统一 `raylea-plugin` 开发工具：检查、通用打包与 Go 构建整合进同一 CLI，替代每插件 `tools/build` 包装器。
- 插件商店收敛：官方目录从插件 GitHub Release 自动生成；管理员可添加自定义 HTTPS 目录；每个来源持久化最后成功缓存；安装检查与确认流程统一。
- 评审修复收口：v0.4 评审 7 个 major 与同轮 minor 全部关闭，覆盖配置快照语义、控制事件顺序、semver 单一实现、菜单安全回归与 fail-closed 分发。

## Contract / Schema 冻结

| 表面 | 目标版本 |
| --- | ---: |
| `plugin-info.schema.json` | 3 |
| `plugin-protocol.schema.json` | 2 |
| `plugin-artifact.schema.json` | 2 |
| `plugin-store-catalog.schema.json` | 2 |
| `plugin-development-workspace.schema.json` | 2 |
| `plugin-management-ui.yaml` / bridge | 3 |
| `backup-manifest.schema.json` | 3 |
| `cli-commands.yaml` | 2 |

- manifest v3 保留 `id`、`name`、`version`、`license`、必填 `min_core_version`、metadata、concurrency、events、permissions、default_config、commands、command_groups、help、management_ui、webhooks。
- 删除 runtime、entry、platforms、plugin_protocol_version、data_schema_version、default_config_file、capabilities、capability_parameters、http_hosts、storage_roots、command_patterns、dynamic_commands、render_templates。
- artifact v2 只记录 artifact_version、target_platform 与 entry；插件身份与版本来自 `info.json`，安装器扫描实际文件。
- fixtures、examples、生成代码与 strict 校验同步冻结；旧版本合同只作为精确拒绝的负向样例。

## 插件协议与 SDK

- protocol v2：只有 init 帧携带协议版本、插件 ID、完整配置快照、生效权限、Bot、管理员、前缀与并发配置；后续帧不重复身份与时间戳。
- `config.changed` 原子替换完整配置快照并携带 changed_keys；空对象表示完整配置为空，缺失或类型错误属于协议违规。
- 事件订阅由 manifest `events` 静态声明；空数组表示不接收普通事件。webhook 在 manifest 中完整静态声明并由宿主自动注册，删除运行时 `event.expose_webhook`。
- 插件私有日志、配置、KV 与文件能力默认可用，仍按调用插件命名空间隔离；跨系统或高权限能力必须在 `permissions` 中声明。删除 `config.read`、动态 webhook 与外部 `message.reply`。
- 删除 `http_hosts`；宿主 HTTP 统一执行 HTTPS、DNS 与重定向复查、SSRF/私网限制、超时与响应体大小限制。
- 插件运行时只要求当前平台可执行文件，不绑定 Go；Go SDK 与 Go 构建器仍作为一等开发工具提供。
- Go SDK v0.4.0：插件 ID 从宿主 init 获取，不再手工配置 ID、事件订阅或最大并发数；控制事件按输入顺序应用后再派发并发业务 handler；使用原子配置快照。
- 版本比较统一为 `server/internal/semver` 单一实现，商店展示、安装门禁与恢复判断共用；pluginmarket 显式要求注入核心版本，无默认回退。
- Dispatcher 缺少权限检查器时拒绝高权限出站动作，不允许 fail-open。
- Vue SDK 同步 bridge v3 生成类型。

## 统一开发工具

- `raylea-plugin inspect` 校验项目 manifest 或展开后的 artifact；`pack` 打包任意已构建的目标平台原生可执行文件。
- `build-go` 自动推导 `cmd/<plugin-id>`、ID 后缀或唯一 cmd 入口，并复用 UI、notices、SBOM、模板与资源流程。
- 相对 `--binary`、`--out`、`--include` 源路径按 `--plugin` 指定的项目根目录解析；绝对路径保持不变。
- 开发工作区 v2 从 `info.json` 推导 ID，临时 go.work 只纳入存在 go.mod 的项目；dev-sync 删除 `--plugin-id`。
- 非 Go 预构建入口固定为 `dist/native/<platform>/<plugin-id>[.exe]`；watch 对该目录例外放行，其他生成目录继续忽略。

## 插件商店与分发

- catalog v2 每个插件只记录当前发布版本；asset 只记录平台、HTTPS 下载地址与归档 SHA-256，允许发布任意一个或多个正式平台。
- 默认官方目录固定为 `RayleaBot/plugin-catalog`，从插件当前 GitHub Release 自动生成，不维护独立签名、公钥注册表或历史版本。
- 管理员可添加和移除自定义 HTTPS 目录；SQLite 持久化每个来源最后一次成功读取的目录，网络不可用时继续使用磁盘缓存，失败刷新不覆盖缓存。
- 安装先经 inspection；首次安装、来源变化或权限扩大时需要确认；同来源且权限未扩大的更新直接进入安装任务；accept 仅传 inspection、包摘要与确认状态。
- 本地目录、ZIP 与远程 ZIP 安装继续使用检查与确认流程；所有安装来源统一校验 `min_core_version`。
- artifact 安装扫描实际文件：拒绝符号链接、路径冲突、缺失入口与错误二进制格式；ZIP 入口固定记录 `0755`。
- 商店详情 API 保留，当前 Web 不提供详情页。
- Go SDK v0.4.0 与六个官方插件（Echo、运势、游戏攻略、订阅与解析、三角洲助手、油价查询）的 Windows x64、Linux x64、macOS arm64 artifact v2 已发布，官方 catalog 收录全部当前版本。

## 管理面与 Launcher

- bridge v3：`management_ui.entry` 只声明一次，页面只保留 `id` 与 `label`，页面 ID 作为路由上下文传递。
- 隔离 origin、CSP、nonce、MessagePort 与密钥保护保持不变。
- 命令统一为 `commands` 数组：每条命令具有稳定 ID 与 exact、pattern 或 setting 触发器；`command_groups` 只能引用真实命令；帮助内容从命令与分组生成。
- 权限、命令 ID、触发方式与命令分组在管理 API、Web 与 Launcher 中与合同一致；插件详情不再展示 runtime、entry、platforms、data schema 与 default config 等无意义信息。
- 商店页支持来源切换与管理、缓存状态、分类、图标失败回退、批量更新与权限确认；桌面与窄屏均保留主要操作。
- 默认配置只允许内联 `default_config`；宿主从 `templates/*/template.json` 自动发现渲染模板。

## 数据保留与备份

- backup manifest v3 拒绝恢复 v2 备份；v3 备份允许收录已经失效的旧 v2 插件包并恢复其数据。
- 旧 manifest v2、protocol v1 与 artifact v1 包不再运行，标记为合同版本不受支持；插件设置、密钥、KV、文件与公开数据不清除。
- 插件有效配置始终是 `default_config` 与持久值合并后的完整快照，持久值优先；init、管理页、command hydration 与 `config.write` 广播使用同一快照；新增默认键逐键补充，不覆盖已有用户值。

# v0.4 Changelog

RayleaBot v0.4 汇总 v0.3.1（2026-08-16）之后的全部变更，对应下一正式版本 v0.4.0；正式发布前随候选修订，发布后作为历史基线归档。前置基线见 [v0.3.md](./v0.3.md)，面向用户的版本说明见 [0.4.0 发布说明](../release/notes/v0.4.0.md)。

开发期间先后以 0.4.0、0.5.0 和 0.7.0 编号构建过候选，均未公开发布，现统一归入 v0.4.0。期间的中间合同（manifest v3、protocol v2 与 v3、管理页 bridge v3）曾随 Go SDK v0.4.0、v0.5.0 和旧版官方插件公开发布；本版只接受 manifest v4 与 protocol v4，中间合同仅作为精确拒绝的负向样例保留。

## 主线交付

- 聊天连接按适配器实例管理：配置 `schema_version` 4 用命名的 `adapters` 列表取代 OneBot 单例，同协议可运行多个实例；身份、凭据、事件、出站路由、黑白名单作用域与入站路径均按实例隔离。QQ 官方机器人成为第二个正式适配器。
- 插件合同重做为 manifest v4、JSONL protocol v4 与 artifact v2：插件是管理员确认安装的可信本地程序，后端可用任意语言实现，安装包只携带目标平台可执行文件；删除宿主权限体系、宿主代理的 HTTP 请求与文件存储、独立插件域与管理页 bridge，管理页改为同源加载。
- 插件交互能力：多轮对话、消息优先级与阻断、后台事件与事件期限、插件之间的服务调用、插件专属命令前缀与兜底命令、插件自带帮助命令、计划任务删除、KV 期限，以及引用插件文件与字体的出图资源。
- 全新分发：默认值内嵌在服务端，`user.yaml` 只保存用户配置；SQLite 从 `000001` 逐步前向迁移到 `000006`；backup manifest v3 只恢复当前格式。不保留 0.3.x 配置、运行数据与插件合同的兼容路径。
- 更新改为版本检查加一键更新：删除发布签名、外置更新程序与更新回滚；桌面完整包由 Launcher 一键更新，服务端包使用 `update download` 与 `update apply`；发布清单宽松读取、严格发布。
- 管理面与 Launcher 重做：Web 迁移到 Reka UI 并重新设计管理壳与各工作区，只提供桌面布局；Launcher 与 Web 共用设计参数，并承担一键更新与服务停启编排。
- 工程：契约驱动的生成物；服务端按职责重组、迁移到 sqlc 并删除不可达代码；消息处理、日志、统计、渲染与插件目录等热路径完成性能优化；CI 收敛为 nightly，发布由同一提交的 nightly 成功记录放行。

## Contract / Schema 冻结

| 表面 | 目标版本 |
| --- | ---: |
| `config.user.schema.json` `schema_version` | 4 |
| `plugin-info.schema.json` | 4 |
| `plugin-protocol.schema.json` | 4 |
| `plugin-artifact.schema.json` | 2 |
| `plugin-store-catalog.schema.json` | 2 |
| `plugin-management-ui.yaml` | 4 |
| `backup-manifest.schema.json` | 3 |
| `deps-manifest.schema.json` | 5 |
| `release-manifest.schema.json` | 2（`plugin_protocol_version` 与 `plugin_manifest_version` 固定为 `"4"`） |
| `cli-commands.yaml` | 2 |
| `websocket-events.yaml` | 1 |
| `web-api.openapi.yaml` `info.version` | 0.5.7 |
| SQLite 当前结构 | `000006` |

- manifest v4 要求 `min_core_version` 不低于 `0.4.0`，拒绝 `0.4.0` 预发布版本；插件构建器执行同样的检查。
- `adapters` 以 `x-collection-key: id` 寻址实例，秘密引用与应用效果 diff 按实例标识解析；入站路径为 `/api/adapters/{id}/reverse-ws` 与 `/api/adapters/{id}/webhook`，各自用所属实例的令牌认证。
- `error-codes.yaml` 是 Server 与 Web 错误码、诊断身份的唯一来源；错误信封不再包含 `message_key`，客户端按 `code` 处理。
- `web-api.openapi.yaml` 的 `info.version` 表示契约修订；发布清单的读取端忽略未知字段，发布端按契约严格生成与校验。

## 适配器与聊天管线

- QQ 官方机器人：应用访问令牌、网关连接与重连、事件规范化与投递、图片 / 视频 / 语音发送与回复、群成员与推送权限事件、发送失败的正式错误码、配置热更新、身份上报与状态发布。
- 中立聊天事件与出站：适配器共享事件转换与重连退避，发送结果与失败与协议无关；出站按适配器实例路由，插件可为主动推送指定适配器。
- 治理与准入：黑白名单与配额按协议、适配器与 bot 身份作用域；权限存储不可用时拒绝准入；每次出站准入绑定一个身份快照。删除按目标的出站熔断与每插件消息限流，按目标限流保留。
- 命令：只按消息中的文字段解析；插件可声明专属命令前缀，同名命令按前缀区分归属；pattern 触发器支持兜底命令；帮助菜单按插件列出生效前缀，插件可以接管“<插件名>帮助”。
- 入站：事件按会话 lane 并行处理，单个会话积压超过 16 条时丢弃新消息；同一用户在一个冷却期内只收到一次冷却提示（`user.cooldown_reply_once`）。
- 消息统计：按连接统计收发消息，记录连接离线与服务中断，经管理接口查询并通过管理事件流推送变化。
- OneBot：动作与元数据按实例路由；协议中心展示已连接账号资料；高负载下的去重、身份缓存与私有连接池完成优化。

## 插件合同、运行时与 SDK

- manifest v4：删除 `permissions`；新增 `priority`、`block`、`services`、`command_prefixes` 与 `help.command`；webhook 只声明 `id`、`route`、`source_cidrs` 与 `max_body_bytes`，验签与去重交给插件。
- protocol v4：init 下发配置快照、`bots`、`timezone` 与生效命令前缀；每个 `event` 帧携带 `deadline_at_ms`；新增 `session.wait`、`session.finish`、`session.expired`、`event.detach`、`plugin.call`、`plugin.request` 与 `scheduler.delete`，`scheduler.trigger` 携带必填的 `payload.task_id`；KV 写入支持期限；删除 `http.request` 与 `storage.file`。
- 运行时：宿主在启动前创建插件的数据目录与缓存目录，经 `RAYLEABOT_PLUGIN_DATA_DIR`、`RAYLEABOT_PLUGIN_CACHE_DIR` 和 `RAYLEABOT_PLUGIN_PACKAGE_DIR` 传入；生命周期操作按插件串行协调；停止遵守宽限期并回收进程树，自动恢复期间保留崩溃计数；每个插件进程最多 256 个未完成 action；只有 `plugin dev-sync` 安装的开发插件逐帧校验入站协议消息。
- 出图：`render.image` 资源可引用数据目录或插件包内的文件，接受字体并以 CSS 自定义属性提供给整页样式，单次最多 512 项（其中 `url` 项最多 16 项）；`template.json` 支持 `fit_width`。
- Go SDK：插件 ID 从 init 获取；提供回调式会话、`Detach`、`DetachWithPropagation` 与 `Deadline`、服务声明与调用、`SchedulerDelete` 和 KV 期限选项；`pluginbuild` 只保留 `Build`、`Pack` 与 `Inspect` 库入口，打包时校验 manifest、命令前缀与 `min_core_version`，不再生成 SBOM。开发期间发布的 Go SDK v0.4.0、v0.5.0 对应 protocol v2、v3，不能与本版宿主握手。

## 插件商店与开发工具

- 商店目录 v2 每个插件只记录当前发布版本，以及各平台的 HTTPS 下载地址与归档 SHA-256；官方目录 `RayleaBot/plugin-catalog` 从插件 GitHub Release 自动生成，不维护签名与历史版本。
- 管理员可以添加和移除自定义 HTTPS 目录；每个来源持久化最后一次成功读取的目录，刷新失败不覆盖缓存。商店说明版本不兼容的具体原因，并支持批量更新。
- 安装：本地插件包一次提交来源并确认信任即创建安装任务；商店插件仅首次安装或来源变化时需要确认；所有来源统一校验 `min_core_version`；安装包上限 1 GiB、解压总量 2 GiB；安装扫描实际文件，拒绝符号链接、路径冲突、缺失入口与错误的二进制格式。
- `raylea-plugin` 统一提供 `inspect`、`pack` 与 `build-go`；开发启动脚本编排本机独立插件仓库，`plugin dev-sync` 支持插件引用的本地模块与 UI 准备脚本，构建缓存与工作区变更按需对账。

## 配置、数据与恢复

- 配置：默认值内嵌在服务端，`user.yaml` 只保存用户配置；保存结果区分已持久化、立即生效与需要重启；热更新按分类路径分派并保留未应用字段；平台密钥只以 `secret://` 引用写入配置。新安装默认监听 `0.0.0.0:8080`。
- 时区：调度、服务日志、管理面时间展示与插件 `init.timezone` 使用同一生效时区，保存的时区变更在重启前不生效。
- SQLite：首次启动逐步事务迁移。`000002` 为插件 KV 增加期限；`000003` 把加密保存的密钥改为原值保存在独立存储；`000004` 新增消息统计与连接、服务中断记录；`000005` 为管理日志增加时间排序与过期清理索引；`000006` 为插件 KV 增加元数据索引。连接池中的每条连接都应用 SQLite 配置。
- 备份与恢复：在线备份通过管理面的 `backup.create` 任务创建；CLI 的备份、恢复与清理要求服务停止并持有生命周期锁。恢复只校验归档完整性与配置、数据库、插件合同版本，目标中的配置、数据库和数据文件必须不存在，不再生成恢复摘要或要求人工确认。
- 日志：时间统一为 UTC 并按 UTC 日期切换文件；收发消息日志显示机器人昵称与发送详情；脱敏覆盖米游社 Cookie、SToken 与抽卡链接中的凭据字段；历史日志分页与清理使用时间索引。

## 更新与发布

- 版本检查：Launcher 每 6 小时经 HTTPS 读取发布清单；Web 通过 `GET /api/update/status` 与 `POST /api/update/check` 查看和检查；CLI 提供 `version --json`、`update check --json`、`update download` 与 `update apply`。
- 一键更新：Launcher 下载更新包后停服，`update apply` 逐个替换程序文件并最后写入 `build_info.json`，新版 Launcher 接管后恢复更新前由它管理的服务；服务端包停服后执行 `update apply`。更新不触碰配置、数据、插件、日志与备份。
- 删除发布签名、外置更新程序、更新回滚与迁移前数据库副本，理由见[更新策略与理由](../release/delivery-and-upgrade.md#更新策略与理由)。
- 发布：中文版本说明经校验后随标签发布；`release.yml` 在构建前和发布前确认同一提交最新一次 nightly 成功；含预发布段的标签发布为 GitHub prerelease 并使用 beta 通道，不更新 latest。

## 管理面与 Launcher

- Web：迁移到 Reka UI 并删除旧 UI 栈；管理壳为可收起的侧栏与单一工作区，只提供桌面布局（以 1920×1080 为最低验证基准）；界面采用白底浅灰卡片与蓝色主操作，字体为随包的 HarmonyOS Sans SC。
- 工作区：配置工作台、按适配器展示的协议中心、插件中心与插件详情（概览看板、实时输出暂停跟随与回到最新）、限流中心、菜单中心、计划任务、日志（筛选即时生效）与诊断（按错误码给出恢复操作）；系统状态页显示各连接的收发消息趋势；管理员可修改凭据；集合分页、请求与下载取消统一处理。
- 插件管理页由 `/plugin-ui/<plugin_id>/` 同源提供，`@rayleabot/plugin-ui` 以当前管理会话调用管理 API；CSP 只允许插件包内脚本，图片与音视频可来自任意 HTTPS 来源。
- Launcher：一键更新；停止、重启与安装更新分别标注停止意图，关闭时等待服务完成清理（最多 30 秒），区分停止与崩溃；缺少 WebView2 时显示安装指引；日志保留最近 7 个 UTC 日期。

## 平台与运行时

- 服务端按职责重组：共享契约、文件与平台包归入 `platform/`，插件 wire 类型归入 `plugins/pluginwire`；路径限制、有界流与原子写入集中到 `fsguard`；仓储查询迁移到 sqlc 并统一事务辅助；删除生产与测试均不可达的代码。
- 接口：删除 `/api/system/metrics` Prometheus 接口，外部探活使用 `/healthz` 与 `/readyz`；就绪检查只报告实际执行的检查，FFmpeg 缺失纳入就绪状态。
- 关闭：先停收新消息，等已收消息回复完成再断开连接；各阶段按统一预算执行，优雅关闭以退出码 0 结束；已接受的任务、插件进程与浏览器继续回收。
- 运行环境：`.deps` manifest v5 在 Server、Launcher 与发布脚本间共享校验；FFmpeg / FFprobe 在管理面按需准备，macOS 使用固定的 GPL 发布构建；Linux 包说明 Chromium 共享库，doctor 检查缺失依赖。
- 认证：签名密钥变更同步更新认证状态并撤销旧会话，`reset-admin` 清除旧签名密钥。
- 性能：消息解析与收发、OneBot 去重与身份缓存、分发协程复用、日志写入与脱敏、消息统计、渲染模板编译、命令目录与商店分页、计划任务详情和 KV 配额核算等热路径减少分配与持锁时间。

## 发布与门禁

- CI 收敛为 nightly 一个工作流，删除 PR 门禁；`repo-checks` 覆盖脚本测试、strict contracts 与生成物漂移；`nightly-status.yml` 维护 nightly 失败 issue。
- 契约与生成物：错误码与诊断目录、插件协议 wire 模型与运行时 schema 从 `contracts/` 生成；Web 类型从 OpenAPI 与 WebSocket 契约生成；CI 检查漂移。
- 测试按风险分层：Web 端到端测试收敛为基于真实 Server 的冒烟，视觉细节交由人工审核；删除低价值测试与恒真断言，修正去掉被测逻辑后仍会通过的测试。
- 候选源码已通过仓库测试、契约与生成物检查、仓库内示例插件构建，以及基于真实 Server 的 Web 冒烟；平台包构建与公开发行物验收在发布时完成，结果登记在[人工 Smoke 登记](../engineering/manual-smoke.md#公开发行物)。

## 延后到后续版本

- Windows 程序代码签名；macOS Developer ID 签名、公证与 Gatekeeper 验收，macOS arm64 保持 experimental。
- 商店详情页（详情 API 保留）、发布者自助上架、插件间依赖解析、插件 OS 强沙盒、多实例高可用。

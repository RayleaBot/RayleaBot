# v0.3 Changelog

RayleaBot v0.3 已交付的能力清单与边界。本文件作为历史基线归档。前置基线见 [v0.2.md](./v0.2.md)。

## 主线交付

- 管理治理：权限策略、黑白名单、限流与命令治理共享正式状态与错误语义，服务端单一裁决。
- 插件信任：只安装平台预编译 Go artifact；安装前检查来源、manifest、文件全集、摘要、平台、二进制与能力，并要求确认可信代码风险。
- 插件分发：主仓库不携带业务插件；签名静态目录、独立插件 Release 与本地开发同步统一复用安装器。
- 自定义管理页：插件提供 Vue 静态产物，宿主从独立插件 origin 加载受限 iframe，交互只通过 bridge v2 的 nonce-bound `MessageChannel`。
- 更新信任框架：签名发布元数据、更新状态、校验规则、事务安装与恢复语义；正式 Authenticode 与真实签名 Windows packaged E2E 因证书门槛未交付。

## Contract / Schema 冻结

- `plugin-info.schema.json`：manifest v2，固定 `runtime: "go"`、协议 v1 与 `management_ui.pages[].entry`。
- `plugin-artifact.schema.json`：artifact v1，固定目标平台与逐文件摘要。
- `plugin-management-ui.yaml` / `plugin-management-ui-bridge.schema.json`：bridge v2 的 manifest HTML 入口、静态路由与 bridge 消息。
- `release-manifest.schema.json`：`release_manifest.v2.json` 与 Ed25519 签名 envelope（原始 manifest SHA-256、主 `key_id`、最多两个签名、双签轮换）。
- `web-api.openapi.yaml`：插件安装检查、插件商店读取、更新状态与更新检查入口。
- `error-codes.yaml`：插件信任、安装检查、更新与恢复错误语义。
- `cli-commands.yaml`：`version --json`、`update check --json`、`update verify --manifest --signature --artifact`。

## 管理治理

- 正式治理入口：`/permission-policy`（超级管理员与默认权限）、`/access-lists`（用户与群黑白名单及白名单启用状态）、`/rate-limits`（命令与外发消息限流、冷却提示）、`/commands`（生效策略与插件声明命令的只读视图）。
- 服务端负责裁决顺序、持久化与错误语义；Web 不从日志或本地副本推断治理状态。

## 插件信任与自定义管理页

- 插件安装先调用检查入口，获得有时效的 inspection id、来源、目标平台、后端摘要、UI 状态与 artifact 校验结果；安装请求回传 inspection id、包摘要与可信代码确认。
- `local_directory`、`local_zip` 与未验证的 `remote_url` 均属于人工信任来源。
- 管理页静态资源由插件专属 origin 只读提供；bridge v2 提供设置、密钥 configured-state、调度、渲染、协议目标与身份解析以及插件管理动作。
- 未验证来源的插件首次打开管理页必须人工确认；确认记录随插件版本或来源变化失效。
- Fortune 与 Subscription Hub 的自定义页面、资源与 bridge 交互验收通过；页面资源限制在声明目录内，管理能力只通过受保护 API 与正式 bridge 提供。

## Go 插件运行时与 SDK

- Runtime Manager 只启动经校验的 Go 可执行文件；安装器只接受平台 artifact 目录或单根目录 ZIP。
- `sdk/go` 提供并发安全 JSONL 客户端、typed local-action helpers 与统一构建器；每个插件保留独立 `go.mod` 与薄 `tools/build`。
- 插件 UI 使用 Vue 3、TypeScript、Vite 与 `@rayleabot/plugin-ui`，资源与后端同包分离存放。
- Python / Node 插件 runtime、SDK、依赖准备器、安装脚本与旧 bridge 已删除；`.deps` v5 管理 Chromium 与 FFmpeg / FFprobe，不提供托管语言运行时。
- 旧插件 epoch 不做数据转换；恢复与原位升级返回 `plugin.reset_required`，管理员、OneBot、治理与审计状态不参与插件重置。

## 插件分发与开发工作区

- 主仓库不包含业务插件源码或产物；运行时只发现 `plugins/installed/`。
- 四个原业务插件由独立 Git 仓库构建三平台 GitHub Release；核心 release 不构建或打包业务插件。
- Server 验证 Ed25519 签名静态目录并向 Web 提供 `/api/plugin-store/**`；Web 不直连目录、GitHub 资产或插件 API。
- 商店安装、本地 artifact 安装与 `plugin dev-sync` 复用同一套 artifact 校验、来源元数据与原子替换/回滚。
- `plugin-workspace.local.json`、临时 Go workspace 与 Vue SDK 镜像支持框架与插件同步开发，不改写独立插件仓库的正式依赖。

## 更新信任与事务安装

- 更新仓库地址与 Ed25519 公钥注册表编译进更新核心；发布元数据固定为 `release_manifest.v2.json` 与 `release_manifest.v2.sig.json`。
- 更新器记录已见最高版本与 manifest digest，拒绝降级、旧清单重放与同版本不同摘要；首个可信更新基线必须手动安装，无法验证 v2 清单的客户端只提供手动升级路径。
- 平台策略：`windows-x64-full` 为 `automatic` 或 `guided`（只有 Ed25519、artifact 摘要、协议版本、平台、版本与 Authenticode 全部通过才可 `automatic`）；`linux-x64-full`、`macos-arm64-full` 为 `guided`；`linux-x64-server` 为 `guided` 或 `manual`。
- 后台每 6 小时检查一次，只展示可用版本；下载与安装必须由用户确认，禁止静默安装。
- 外置 `raylea-updater.exe` 在安装根之外运行，重新验证 manifest 签名、artifact 摘要、Authenticode signer、平台、版本与归档边界，再执行「停止旧服务 → 离线备份 → 同卷 staging 解包 → restore 与 preflight → 双 rename swap → postflight → 提交事务 / 回滚」。
- 同一插件 epoch 内事务保留 `config/user.yaml`、`data/**` 与 `plugins/installed/**`；旧插件 epoch 在 preflight 以 `plugin.reset_required` 拒绝；任一 postflight 失败回滚并恢复旧服务，回滚失败进入 `rollback_failed` 并禁止自动启动；旧版本与离线备份至少保留 7 天，并至少保留到下一次成功升级。
- 状态：`disabled | idle | checking | up_to_date | update_available | downloading | ready_to_install | installing | succeeded | failed | rolled_back | rollback_failed`；阶段：`metadata | artifact | backup | extract | preflight | stop | swap | postflight | commit | rollback`。
- Web API：`GET /api/update/status`、`POST /api/update/check`，Web 只查看与检查更新。Launcher 承载用户确认与 Windows 安装编排，消费共享更新核心，不维护平行状态。

## 发布与门禁

- strict contracts 与 fixtures、generated drift、Go SDK/插件 `-race`、三平台 plugin artifact、server build 与 binary govulncheck、Vue SDK/页面与 Web/Launcher typecheck/test/build/E2E、四种发布归档检查、doctor、文档链接检查与 `git diff --check`。
- 共享验签、重放防护与下载边界由单元测试与故障注入覆盖：错误 key、过期、重放、摘要、大小与磁盘不足。
- 外置 updater 每个 journal 阶段的中断恢复与 postflight 回滚验证通过；Web、CLI、Launcher 三个入口共享状态、错误与可信结果。

## 延后到后续版本

- 正式 Authenticode 签名与真实签名 Windows packaged E2E：证书可用前 `windows-x64-full` 保持 `guided`，自签名证书不能替代验收。
- 发布者自助上架、评分评论、付费市场。
- 插件间依赖解析、插件 OS 强沙盒。
- 多实例高可用、非 OneBot 多协议。

RayleaBot 0.4.0 是 0.3.1 之后的首个功能版本：聊天连接按适配器实例管理并新增 QQ 官方机器人；插件改为可用任意语言实现的原生程序，支持多轮对话、消息优先级、后台事件和插件之间的服务调用；管理面与启动器重新设计，桌面完整包支持一键更新。当前尚未公开分发，本文用于候选包安装与验收。

> [!IMPORTANT]
> 0.3.x 与本版不兼容：配置、备份和插件包都不能沿用，也不能覆盖升级，需要在新目录全新安装。插件需要按 manifest v4 重新构建，见下文“0.3.x 兼容性”与“开发者说明”。

## 本次重点

- **多实例聊天连接与 QQ 官方机器人**：配置以命名的适配器实例列表取代 OneBot 单例，同一协议可以接入多个账号，也可以只接入 QQ 官方机器人；身份、凭据、事件、出站路由与黑白名单作用域都按实例隔离。QQ 官方机器人支持网关连接与重连，以及图片、视频、语音与文件的发送和回复；群管理员开启“接收全部群消息”后，只处理 @ 机器人的消息。插件回复按被动回复引用触发消息，超出回复时限或次数时改为主动推送；含不支持消息段的消息整条不发送，不会只发出文字。
- **原生插件与插件商店**：插件是管理员确认安装的可信本地程序，后端可以用任意语言实现，安装包携带目标平台的可执行文件；宿主不编译源码，也不再代理插件的网络与文件访问。插件商店读取官方目录和管理员添加的 HTTPS 目录，网络不可用时使用每个来源最后一次成功读取的结果；插件管理页与管理面同源加载。
- **插件交互能力**：插件可以登记多轮对话的下一条输入，用户回复无需重复命令前缀；可以声明消息优先级与阻断，把扫码登录等分钟级流程转入后台事件，按服务名调用其他插件，并声明专属命令前缀与兜底命令；插件私有 KV 支持期限。
- **管理面、启动器与更新**：Web 管理面与 Launcher 重新设计。配置保存结果区分已保存、立即生效与需要重启，诊断按错误码给出恢复操作，系统状态页显示各连接的收发消息趋势。桌面完整包在 Launcher“关于应用”中确认后一键更新；服务端包先在服务运行时执行 `raylea-server update download` 准备更新，再停服执行 `raylea-server update apply`。

## 其他改进

- **配置与时区**：配置格式为 `schema_version: "4"`，默认值内嵌在服务端，`user.yaml` 只保存用户配置；调度、日志显示与插件收到的 `init.timezone` 使用同一生效时区。
- **命令与帮助**：命令只按消息中的文字段解析，@ 等非文字内容不再影响匹配；插件仍可从消息段读取被 @ 的用户。帮助菜单按插件列出生效前缀，用法写成可直接发送的完整命令；插件可以指定自带的帮助命令，“<插件名>帮助”交由插件按自己的样式回复。
- **冷却与入站**：同一用户在同一个群或私聊中，一个冷却期内只收到一次冷却提示，可在限流中心关闭；目标外发额度已满时直接放弃提示。入站消息按会话分开处理，一个群拥堵或被刷屏时，同一连接下的其他群照常处理；单个会话积压超过 16 条时丢弃新消息。
- **出图与插件包**：`render.image` 可以引用插件数据目录或插件包内的图片与字体，模板可以按页面内容确定出图宽度。安装包上限提高到 1 GiB、解压总量 2 GiB，以容纳随包分发的模板素材。
- **日志**：日志时间统一为 UTC 并按 UTC 日期切换文件，管理面仍按配置时区显示；收发消息日志显示机器人昵称与发送详情；脱敏覆盖米游社 Cookie、SToken 与抽卡链接中的凭据字段。管理日志改为后台批量写入数据库，记录日志不再等待磁盘提交；进程异常退出时可能丢失最后一批尚未写入的管理日志，控制台输出不受影响。
- **关闭与回收**：停止服务时先停收新消息，等已收消息回复完成再断开连接；插件停止遵守宽限期并回收进程树，已接受的任务、插件进程与浏览器在关闭时继续回收。
- **运行环境**：FFmpeg / FFprobe 改为在管理面按需准备，Windows 与 Linux 改用共享库构建，下载量约减半；macOS 使用固定的 GPL 发布构建，保留 libx264/libx265。Linux server 包补充 Chromium 共享库说明，doctor 检查缺失依赖。Windows Launcher 在 WebView2 缺失时显示安装提示，Launcher 日志保留最近 7 个 UTC 日期。启动器界面改用与管理面相同的组件与图标。
- **更新来源**：在“配置 → 版本与更新”中可以选择稳定版或测试版通道、固定目标版本，不执行降级。默认同时检测 GitHub 直连与三个公共加速源并自动选路，下载失败时切换来源；这些第三方服务被视为受信的分发路径，不信任时可删除地址或改为直连。`update download --file` 可导入另一台设备取得的发布包，准备与安装都不联网。
- **诊断包**：管理面导出的诊断包新增 goroutine 栈、内存 profile 与运行时指标快照，便于定位卡死与内存增长；这些内容不含消息正文。
- **认证**：管理会话改为随机令牌，数据库与备份只保存令牌的哈希，泄露的备份或数据库文件不能用来伪造登录。

## 精简与移除

- **更新**：删除发布清单与插件目录的签名、外置更新程序与更新回滚；更新改为经 HTTPS 检查版本，再一键更新，或依次执行 `update download` 与 `update apply`。取舍理由见[更新策略与理由](../delivery-and-upgrade.md#更新策略与理由)。
- **插件权限与宿主代理**：删除插件权限声明、宿主代理的 HTTP 请求与文件存储；插件自行发起网络请求，并读写宿主注入的数据目录。
- **插件管理页**：页面由 `/plugin-ui/<plugin_id>/` 提供，局域网部署不再需要单独的插件页面域名。响应 CSP 只允许加载插件包内的脚本，禁止内联脚本与 `eval`；通过 IPv6 字面地址访问时 CSP 无法写出主机，放宽为同源脚本。图片与音视频可以来自任意 HTTPS 来源，例如直接显示 QQ 头像；样式、字体与网络请求仍限同源。
- **插件安装**：本地插件包一次提交来源并确认信任即创建安装任务；商店插件仅首次安装或来源变化时需要确认。
- **恢复**：只校验归档完整性与配置、数据库、插件合同版本，不再逐个评估插件，也不生成恢复摘要或要求人工确认。恢复目标中的配置、数据库和数据文件必须不存在，常规做法是恢复到新解压的目录。
- **出站**：删除按目标的出站熔断与每插件消息限流，按目标限流保留。
- **管理与接口**：删除 `/api/system/metrics` Prometheus 接口，外部探活使用 `/healthz` 与 `/readyz`；错误信封删除 `message_key`，客户端按 `code` 处理；管理面移除 OneBot 兼容矩阵面板，矩阵见 [OneBot 兼容说明](../../dev/onebot-compatibility.md)。
- **密钥存储**：删除与密钥同表保存的加密层，平台密钥改为原值保存在独立存储；配置继续只保存 `secret://` 引用，管理面不回显。
- **界面布局**：Web 管理面只提供桌面布局，以 1920×1080 为最低验证基准，手机与平板不提供专门布局。

## 升级说明

### 0.3.x 兼容性

0.3.x 与 0.4.0 不兼容。0.3.x 的更新器依赖已移除的签名资产，不能自动升级到本版：本版成为 GitHub latest 后，0.3.x 检查更新会报告发布清单无效；预发布不改变 latest，旧版在此期间仍显示“已是最新”。

0.3.x 的配置 schema v3、backup manifest v2 和插件 manifest v2 均不受本版支持。不能直接覆盖升级、使用本版 `restore` 恢复旧备份，或仅修改版本号。请在新目录全新安装并初始化 0.4.0，使用与本版兼容的 v4 插件包；不提供旧格式迁移。

新安装默认监听 `0.0.0.0:8080`，局域网中的设备可以直接访问管理面和适配器入站地址；0.3.x 默认只监听本机。只在本机使用时把 `server.host` 改为 `127.0.0.1`；开放到局域网时为适配器设置访问令牌，并用防火墙限制来源。见[部署指南](../../user/deployment.md)。

### 早期候选安装

- **升级范围**：适用于 0.3.1 之后未公开分发的候选安装，即构建时标识为 0.4.0、0.5.0 或 0.7.0、配置为 `schema_version: "4"` 的安装。这些安装的版本号不低于本版，版本检查不会提示更新，需要手动更新：停止服务，执行 `raylea-server backup`，把发布包根目录内容解压覆盖到安装根，再启动。
- **配置**：配置格式仍为 `schema_version: "4"`。新增 `user.cooldown_reply_once`，缺少时按默认值开启。候选期间删除的字段（如 `http` 段、`web.plugin_ui_origin_template`、出站熔断、每插件限流与插件 IPC 限流相关字段）按未知字段忽略，不影响加载。
- **数据**：SQLite 在首次启动时由 `000001`–`000007` 逐步事务迁移到 `000008`，迁移内容与耗时见[手动更新](../delivery-and-upgrade.md#手动更新)。`000007` 会改写管理日志表，日志较多时首次启动更慢，时间无法解析的历史日志行在迁移中删除；`000008` 使已有登录会话失效，升级后需要重新登录，账号和密码不变。迁移后旧版本核心不能读取新结构，退回旧版本需使用旧发布包与升级前的备份。备份清单仍为 v3，候选生成的备份可以恢复到本版，首次启动时迁移。
- **插件**：插件数据保留在 `data/plugins/<plugin_id>/`。manifest v3 / protocol v3 插件显示为合同不受支持并保持禁用，安装按 v4 重新构建的版本后再启用。
- **操作方法**：[升级指南](../delivery-and-upgrade.md)、[恢复步骤](../../user/recovery.md)。

## 开发者说明

插件合同为 manifest v4、JSONL protocol v4 与 artifact v2，`min_core_version` 必须为 `0.4.0` 或更高，不接受 `0.4.0` 预发布版本。0.3.x 的插件（manifest v2 / protocol v1）与按 Go SDK v0.4.0、v0.5.0 构建的插件（manifest v3 / protocol v2、v3）都不能在本版运行，需要用随本版发布的 Go SDK v0.6.0 重新构建；其他语言实现按[插件协议](../../plugin/protocol.md)更新。

- **工具链**：源码构建使用 Go `1.27.2`、Node.js `26.10.0`、npm `11.19.1` 与 pnpm `11.25.0`，仓库脚本改由 Go 与 Node.js 实现，不再需要 Python；Corepack 保持 `0.35.0`，sqlc 保持 `1.31.1`。升级开发环境后按 lockfile 重新安装依赖；CI 与开发容器使用相同基线，详见[工程基线](../../engineering/baseline.md)。
- **构建与分发**：安装包必须包含目标平台的原生可执行文件，宿主运行期不编译源码或安装依赖。Go 插件使用 `raylea-plugin build-go`，其他语言先构建原生入口再使用 `raylea-plugin pack`；构建目标为 `windows-x64`、`linux-x64` 或 `macos-arm64`。商店目录每个插件只记录当前发布版本，以及各平台的 HTTPS 下载地址与归档 SHA-256；Server 读取目录时忽略未知字段和不认识平台的资产，目录今后增加字段不影响本版刷新。见[插件 SDK](../../plugin/sdk/README.md#raylea-plugin)与[插件开发与分发](../../plugin/store-and-development.md)。
- **SDK 许可**：Go SDK（含 `raylea-plugin`）与 Vue SDK 改用 MIT 许可，主仓库其余部分仍为 AGPL-3.0；插件只链接 SDK 时可以自行选择许可。
- **QQ 官方投递**：处理 QQ 官方消息事件期间向同一会话发送的消息按被动回复投递；`at` 转为 `<qqbot-at-user>` 文本标记，媒体支持 `base64://`，不支持的消息段使整条消息不发送。逐段规则见[插件协议](../../plugin/protocol.md#qq-官方机器人的投递规则)。
- **多实例身份**：事件携带 `source_adapter` 与 `source_protocol`，主动发送需要选择目标实例；`init.bots` 与 `bot.identities.changed` 提供各适配器的身份快照，`init.timezone` 传递宿主生效时区。
- **权限、网络与文件**：manifest 删除 `permissions`，init 删除 `effective_permissions`，错误码 `plugin.permission_denied` 删除；宿主动作不再按插件声明授权。删除 `http.request` 与 `storage.file` 动作，Go SDK 同步删除对应方法。插件使用自带的 HTTP 客户端，持久化文件直接写入环境变量 `RAYLEABOT_PLUGIN_DATA_DIR` 指向的目录，可重建的缓存写入 `RAYLEABOT_PLUGIN_CACHE_DIR`，该目录不随业务数据备份；插件包目录经 `RAYLEABOT_PLUGIN_PACKAGE_DIR` 传入，包内随附文件只读。
- **出图**：`render.image` 资源新增 `path`，引用数据目录内插件自行下载或生成的文件，数据目录没有时读取插件包内的同一路径；单次最多 512 项，其中 `url` 项仍最多 16 项。资源另接受字体（以资源 ID 注册为字体族），图片同时以 CSS 自定义属性 `--render-resource-<id>` 提供给整页样式，带 `data-render-resource` 的非图片元素可用 `var(--render-resource)` 作背景。`template.json` 新增 `fit_width`，出图宽度可随页面内容确定；`body` 隐藏溢出时高度按 `body` 自身的盒子测量。见[插件协议](../../plugin/protocol.md)与 [Plugin Manifest](../../plugin/manifest.md)。
- **服务调用**：manifest 新增 `services`，协议新增 `plugin.call` 动作、`plugin.request` 事件与服务路由错误码，Go SDK 提供服务声明与调用。协议没有取消帧，调用期限与失败语义见[插件协议](../../plugin/protocol.md)。
- **命令与帮助**：manifest 新增 `command_prefixes`，`init.command_prefixes` 改为下发对该插件生效的前缀；pattern 触发器新增 `fallback`，兜底命令只在所有插件的普通命令与内置帮助菜单都未命中时参与匹配；`help.command` 指定插件自带的帮助命令，须为 exact 触发。
- **计划任务**：新增 `scheduler.delete` 动作与 Go SDK 的 `SchedulerDelete`，插件只能删除自己创建的任务。`scheduler.trigger` 的 `payload.task_id` 必填，Go SDK 以 `Event.TaskID()` 读取，插件按它分派触发并删除无法识别的任务。任务的执行耗时从触发时刻起算，包含排队时间。
- **后台事件与期限**：每个 `event` 帧携带处理期限 `deadline_at_ms`，Go SDK 的 handler context 在该期限结束。新增 `event.detach` 动作与 `runtime.plugin_detached_event_timeout_seconds`、`runtime.max_detached_events_per_plugin` 配置；Go SDK 提供 `Detach`、`DetachWithPropagation` 与 `Deadline`，转入后 `SendText`、`Send`、`Reply` 以普通消息动作加终态结束。见[插件协议](../../plugin/protocol.md#后台事件)与[插件 SDK](../../plugin/sdk/README.md#后台事件)。
- **Webhook**：manifest 声明只保留 `id`、`route`、`source_cidrs` 与 `max_body_bytes`，删除内置 token、签名、secret 引用与重放保护。`webhook.received` 的 `raw_payload` 携带请求头，并以 `body_text` 或 `body_base64` 保留原始正文，插件按对方平台规则自行验签与去重。
- **管理页**：bridge 退役。`@rayleabot/plugin-ui` 以当前管理会话直接调用管理 API，并读取宿主主题变量；外部 CDN 脚本和内联脚本会被 CSP 拒绝，需打包进插件管理页资源；HTTPS 图片与音视频可以直接引用。见[插件管理页](../../plugin/management-ui.md)。
- **对话、优先级与 KV**：新增 `session.wait`、`session.finish` 与 `session.expired`，manifest 新增 `priority` 与 `block`，KV 写入支持期限。见[插件 SDK](../../plugin/sdk/README.md)。
- **帧校验**：正式插件不再逐帧校验协议消息，只有 `plugin dev-sync` 安装的开发插件校验入站帧并给出诊断；单帧大小上限、stderr 截断，以及每个插件进程最多 256 个未完成 action 的上限保留，超出时返回 `platform.rate_limited`。插件构建不再生成 SBOM，许可证与第三方声明保留。

RayleaBot 0.4.0 是本轮全新分发的候选版本，提供 OneBot11 与 QQ 官方机器人多实例接入、原生插件和本地管理。当前尚未公开分发，本文用于候选包安装与验收，不代表正式发布或全部平台验收完成。

## 本次重点

- **按实例管理聊天连接**：身份、凭据、事件和出站路由按适配器隔离，支持同协议多实例、仅 QQ 官方实例及无适配器配置。
- **插件操作保持真实结果**：安装、卸载、启停和重载按插件串行协调；失败保留错误及必要的恢复文件。HTTP 与插件动作共用设置服务，生效通知失败可明确重试。
- **配置与数据有明确来源**：正式 schema 提供默认值，`user.yaml` 保存用户配置；配置保存结果区分已持久化、立即生效和需要重启。SQLite 从当前结构初始化。
- **管理与资源回收更可靠**：Web 请求支持取消、超时和合并刷新；诊断按错误码展示恢复操作。服务关闭继续回收已接受的任务、插件进程与浏览器，并保留实际失败结果。

## 候选产物与首次安装

以下是本版的目标产物名称；实际生成、校验和平台验收结果以交付记录为准。目前不提供未经确认的下载地址。

| 环境 | 目标产物 | 入口 |
| --- | --- | --- |
| Windows x64 桌面 | `RayleaBot-v0.4.0-windows-x64-full.zip` | `RayleaLauncher.exe` |
| Linux x64 桌面 | `RayleaBot-v0.4.0-linux-x64-full.tar.gz` | `RayleaLauncher` |
| macOS Apple Silicon | `RayleaBot-v0.4.0-macos-arm64-full.tar.gz` | `RayleaLauncher.app` |
| Linux x64 服务端 | `RayleaBot-v0.4.0-linux-x64-server.tar.gz` | `raylea-server` |

1. 使用本版候选包，在空的、可写的固定目录解压，保留完整目录结构。正式发布包的清单、摘要与签名校验要求见[交付说明](../delivery-and-upgrade.md)。
2. Windows Launcher 需要系统 WebView2 Runtime；Linux 桌面需要 GTK 3 与 WebKit2GTK 4.1。图片渲染需要可用的系统 Chrome、Chromium、Edge 或已准备的托管 Chromium；FFmpeg / FFprobe 按运行环境清单准备。运行预编译包无需安装 Go、Node.js 或插件语言依赖。
3. 启动 Launcher；它在缺少用户配置时调用服务端初始化。直接运行 Server 时，可先在安装根执行 `raylea-server config init`，再启动 `raylea-server`。Windows 命令使用 `./raylea-server.exe`。
4. 打开 `http://127.0.0.1:8080`，按页面与本机服务输出的指引创建管理员并登录。默认仅开放本机管理；远程部署需按[部署指南](../../user/deployment.md)配置公开 origin、HTTPS 代理和独立插件域。
5. 在协议中心添加并配置适配器实例，再安装所需业务插件。默认 `adapters` 为空；主程序包不内置业务插件。

配置格式为 `schema_version: "4"`，默认值内嵌在服务端；SQLite 当前结构版本为 `000001`。访问令牌与平台密钥由 secret store 保存，配置文件保留引用。配置保存后如出现需重启项或应用失败组，应先检查提示和连接状态。详见[配置说明](../../user/configuration.md)。

## 插件构建与接入

本版使用 manifest v3、JSONL protocol v3、artifact v2 和管理页 bridge v3。后端可以由任意语言实现，但安装包必须包含目标平台原生可执行文件；宿主运行期不编译源码或安装依赖。多身份事件使用 `source_adapter` 与 `source_protocol`，主动发送需选择目标实例。基于协议 v2 SDK 构建的插件不能与本版宿主握手，须用当前 Go SDK 重新构建，其他语言实现按 `contracts/plugin-protocol.schema.json` 更新；身份数组与黑白名单作用域规则见[插件协议](../../plugin/protocol.md)。

Go 插件可使用当前 Go SDK 和 `raylea-plugin build-go`；其他语言先构建原生入口，再使用 `raylea-plugin pack`。构建目标为 `windows-x64`、`linux-x64` 或 `macos-arm64`，并核对 manifest 的 `min_core_version` 与目标核心版本。完整命令见[插件 SDK](../../plugin/sdk/README.md#raylea-plugin)。 Go SDK 的 `pluginbuild` 包提供 `Build`、`Pack` 与 `Inspect` 库入口，不再包含解析命令行参数的 `Main`；自定义构建脚本改为调用 `raylea-plugin build-go` 或直接调用 `Build`。

插件通过 HTTPS 商店目录或本地 artifact 安装；来源、归档 SHA-256、平台、入口和权限均参与检查。目录摘要校验不等同于代码安全保证，插件后端按完全可信本地代码运行。管理页采用独立 origin 和 bridge；官方页面使用 Vue 静态产物。详见[插件开发与分发](../../plugin/store-and-development.md)。

## 本版备份与恢复

运行中的在线备份通过管理面的 `backup.create` 任务创建。CLI 的备份、恢复和清理要求目标服务已停止；锁被占用时返回失败。

```text
raylea-server backup
raylea-server -config <目标目录>/config/user.yaml restore <本版备份路径>
raylea-server -config <目标目录>/config/user.yaml doctor
```

备份命令输出实际备份路径。本版使用 backup manifest v3，归档配置、SQLite 快照、插件安装包和业务数据。恢复时先校验归档与当前结构，再写入空目标目录；完成后用同一配置启动，检查管理员登录、插件状态和恢复摘要。失败时保留错误与必要的回滚文件，处理前不要删除报告中的恢复工作目录。详见[恢复步骤](../../user/recovery.md)和 [CLI](../../user/cli.md)。

## 验证范围与发布限制

已核实的测试、Windows 实包原生 UI、插件与 PNG 功能流程，以及托管检查结果统一记录在[0.4.0 候选版验收记录](../validation-v0.4.0.md)。其中注明具体源码与归档、观察窗口、失败修复及未验证范围；早期候选包通过不代表后续构建自动通过。

安装前应核对交付记录中的源码提交、归档摘要与对应平台结果。不同提交的构建不能沿用另一份候选包的通过记录。

Windows 候选包保持 `guided`，不提供自动事务安装。自动安装需要正式 Authenticode 证书及真实签名 Windows packaged E2E；Ed25519 清单签名不能替代 Authenticode。清单验签、产物摘要、许可证和 smoke 结果分别记录在交付证据中。

macOS 候选包采用链接器 ad hoc 签名，本轮不包含 Developer ID 签名、公证或 Gatekeeper 验收。具体归档与检查范围见[候选版验收记录](../validation-v0.4.0.md)。

## M1 / M2 组件和交互

产品组件集中负责按钮变体、字段标签与错误关联、字符串与数值输入、密码可见性、单选与多选、复选框、开关、状态反馈、弹窗和确认。组件展示页位于开发构建的 `/__dev/components`，要求管理会话，生产产物不包含该入口。

弹窗位置由 CSS 固定在视口中心。Motion 以 220ms 播放透明度和 `0.96 → 1` 缩放，以 160ms 退出；内容高度通过实际测量插值，较短视口由正文区域滚动。减少动态效果和强制配色环境使用即时状态变化。嵌套弹窗与选择器通过共享浮层顺序排列，主按钮前景使用共享 `on-brand` token。

Reka 的交互节点保持挂载，直到 Motion 完成退出后才释放遮罩、滚动锁和焦点锁。仅在 Reka 外包裹 AnimatePresence 会出现“画面还在退出、交互已卸载”的问题；当前产品封装由 Motion 完成事件控制 `active` 状态。兼容矩阵等业务内容也由这一层统一控制挂载。

### 类型检查入口修正

原命令 `vue-tsc --noEmit` 只读取顶层空 `files` 配置，没有遍历应用和 Node 引用工程。入口现为 `vue-tsc --build`，同时补齐测试工程的浏览器类型环境。由此发现的适配器类型别名缺失、既有 WebSocket 适配器快照分支未生成和旧 Antd token 名称错误已修复。

正式日志筛选枚举目前仅包含 OneBot11。QQ 连接的诊断入口进入实时日志，不发送契约外的协议筛选值。

## M3 应用壳与认证入口

导航、插件子导航、工作区页签及右键菜单、搜索、设置抽屉、主题菜单和登录表单已使用产品控件。原工作区身份、缓存与恢复、插件管理深链、正式登录和错误处理仍由既有模块负责。页面内的旧组件暂时继续使用顶层 Antd 主题 provider。

左右抽屉复用 AppDialog 的焦点与退出生命周期，以固定视口高度滑入；居中弹窗单独对内容高度插值。不能给居中模式绑定空的内联高度，否则 Vue 更新会打断 Motion 的插值。菜单触发抽屉后，离场菜单位于新浮层下方；触发项卸载时，关闭操作回到仍有效的菜单按钮。

登录保留青瓷玻璃材质，账号与密码使用相同的 50px 输入框、错误关联和焦点样式。密码可见性按钮支持键盘与忙碌禁用。全局提示由 Reka Toast 负责时限和可访问性，保留原业务反馈函数；同时最多显示四条，错误提示留置更久，并提供关闭操作。

已通过完整类型检查、生产构建，以及登录表单、认证主题和导航动效的 12 项单元测试。18 项浏览器回归在同一批次通过，包含协议浮层回归、偏好持久化、菜单到抽屉的焦点交接、键盘搜索、折叠导航、插件筛选与展开、页签关闭、认证和 `360/768/1280px` 视口。

独立视觉评审发现上游 Tooltip 的 `max-w-xs` 与项目 `--spacing-xs` 映射冲突，导致提示逐字换行。组件已改为明确的 `min(20rem, 视口宽度 - 24px)` 上限；新增搜索、全屏和设置三种提示的浏览器回归通过，本阶段共覆盖 19 项浏览器用例。六张同路径截图已重截；评审复核将宽度问题和 M3 文档交接均判定为已解决，结论为 `ship`，范围限于这两项发现。

## M4-C 系统状态与诊断工作区

系统状态、恢复兼容性、日志筛选、调度详情和模板预览控件已迁移。原生表格保留调度操作列固定位置；查看任务使用统一居中弹窗。恢复确认仍按 review ID 选择并提交，日志筛选仍保留多值、未知插件 ID、协议清除和本地时间范围。

Reka 选择器的鼠标打开过程不保证触发原生 focus，因此共享组件提供打开事件；插件筛选在获得焦点或实际打开时加载选项，保留按需读取与重复请求抑制。桌面日志详情维持非模态浮窗和既有拖动边界，关闭后回到有效日志行；移动端复用右侧抽屉。详情展示层保留退出前的最后一份内容，不改变控制器的正式选择状态和请求缓存。

模板 iframe 的外层容器负责居中，内层改为左上角缩放，避免缩小后向右偏移并被裁切。浏览器回归核对桌面、窄屏和平板宽度的实际边界，调整视口时保留同一预览文档。调度统计条移除宽度 CSS 动画；列表条目不增加入场动画。

现有 8 个组件测试文件共 40 项通过；17 项既有浏览器回归覆盖实时与历史日志、滚动跟随、手动滚动、分页、隐藏恢复、转义、重复筛选、按需选项、跨工作区跳转、备份诊断和模板自动预览。另有 5 项新增浏览器回归通过，验证逐帧退出、焦点、非模态拖动、未知筛选清除和模板缩放，本批共 22 项不同用例。9 项共享浮层与应用壳回归、完整类型检查、生产构建、缩进、设计 token、颜色和文档门禁也已通过。

### 日志与 iframe 稳定性

真实 WebSocket 流追加 160 条日志后，在 `scrollTop=300` 的阅读位置继续追加 20 条；列表高度从 13,040 增至 14,640 px，滚动位置和首个渲染条目保持不变。

性能对照发现，迁移后的级别标签使单行日志从 80 增至 82 px，首次滚动触发连续尺寸修正，p95 曾达到 50–66.7ms。日志级别标签恢复紧凑的 22px 高度后，常见单行日志重新与 80px 预估一致；字号、动态长文本测量与虚拟列表实现保持不变。实际修复产物在三个新上下文中各完成三轮 180 条日志的快速滚动，九轮 p95 为 16.7–16.8ms，均无超过 50ms 的任务。既有浏览器测试增加了均匀日志在跨区域滚动后总高度稳定的断言，覆盖这次回归。

模板 iframe 在 `1440`、`390`、`768` 宽度下保留同一节点，实际左右边界分别为 `670–1398`、`22–368`、`34–734` CSS px，均在视口内。基准的相同缩放会向右溢出裁切；M4-C 的左上角缩放原点修复在正式产物上得到确认。

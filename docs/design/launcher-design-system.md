# RayleaBot Launcher Design System

本规范服务于 `launcher/` 的 Wails 桌面启动器。项目级视觉语义以根目录 [`DESIGN.md`](../../DESIGN.md) 为准；Launcher 使用 Vue 3.5、Reka UI、Motion for Vue、Lucide 图标、Go 桌面宿主和生成的 typed bindings，与 Web 管理面共用同一套前端栈。

## 产品职责

- Launcher 是本机服务壳、环境预检入口和 Web 管理面入口，不复制 Web 的业务页面或服务端状态机。
- 界面优先回答服务是否可用、是否需要人工处理、当前可以执行什么操作。
- 主操作保持唯一突出：正式可用性允许打开 Web 时显示“管理界面”，否则显示现有启动动作。停止保持危险次级操作及现有确认规则；重置与退出沿用既有危险语义，工具操作保持低权重。
- 系统诊断、恢复和运行环境状态直接展示正式服务结果，不从日志文本推断状态。

## 主题与 token 映射

Launcher 支持 `system`、`light` 和 `dark`，首次显示跟随系统，显式选择可持久化，不提供按时钟自动切换配置。根元素上的 CSS variables 与原生窗口背景使用同一有效主题，窗口背景、原生控件和自定义表面保持一致。画布与 Web 管理面相同，浅色主题为纯白、暗色主题为炭黑；侧栏、内容分组与浮层等盒子使用浅灰表面，文字、边框和选中背景使用中性色；蓝色用于主操作，品牌链接、焦点和勾选标记使用品牌前景色。`design/tokens.json` 是主题 token 的唯一机器值源，`launcher/src/shared/launcher-theme-tokens.generated.ts` 提供生成值，`launcher-theme.ts` 保留既有消费接口。

主题入口使用显式菜单，按“跟随系统、浅色、深色”排列并显示当前单选项。菜单打开时以 `220ms` 从 `0.96` 缩放淡入，选择或取消后立即关闭，焦点回到触发按钮。选择新主题后，新主题从主题按钮中心以 `420ms` 圆形展开到整个窗口；跟随系统自动切换时新主题以 `280ms` 淡入。`prefers-reduced-motion` 下立即完成开合与主题切换。

| 产品语义 | Launcher 角色 | 浅色 token | 暗色 token |
| --- | --- | --- | --- |
| 窗口画布 | 页面与窗口背景 | `light-canvas` | `dark-canvas` |
| 内容表面 | 侧栏、内容分组、Dialog 与菜单等盒子 | `light-surface` | `dark-surface` |
| 抬升表面 | 盒子内的控件与所有文本输入 | `light-surface-raised` | `dark-surface-raised` |
| 柔和表面 | 画布上的控件悬停、日志凹槽与中性图标底 | `light-surface-soft` | `dark-surface-soft` |
| 导航 | 侧栏盒子与选中胶囊 | `light-chrome`、`light-nav-selected` | `dark-chrome`、`dark-nav-selected` |
| 主文本 | 标题、正文与控件文字 | `light-text` | `dark-text` |
| 次文本 | 说明、标签与元数据 | `light-text-muted` | `dark-text-muted` |
| 边界 | 盒子内分隔线 | `light-border` | `dark-border` |
| 控件边界 | 文本输入、单选与复选框边框 | `light-control-border` | `dark-control-border` |
| 主操作填充 | 主按钮、选中选项的勾选圆标与勾选后的复选框 | `light-primary` | `dark-primary` |
| 品牌前景 | 品牌链接、选中导航图标和勾选标记 | `light-brand-foreground` | `dark-brand-foreground` |
| 焦点 | 全局焦点轮廓与文本输入焦点 | `light-focus` | `dark-focus` |
| 品牌填充内容 | 品牌填充上的文字与符号 | `on-brand` | `on-brand` |
| 人工关注 | 本地 attention token | `light-attention` | `dark-attention` |
| 状态 | 成功、警告与危险语义色 | 浅色语义 tokens | 暗色语义 tokens |

人工关注色只标记需要操作者判断或确认的事项，不替代 warning、danger 或普通 primary action。

服务状态使用固定色调映射，状态透镜与侧栏底部的状态圆点共用同一语义与状态符号：

| 服务状态 | 色调 | 含义 |
| --- | --- | --- |
| `stopped` | neutral | 服务处于普通停止状态 |
| `starting`、`stopping` | info | 启动器正在执行系统操作 |
| `running` | success | 服务可用 |
| `degraded` | warning | 服务可用但运行条件受限 |
| `setup_required` | info | 待初始化：服务已启动但还没有管理员账号，主操作打开管理界面的初始化页；外部启动的服务提示使用其控制台显示的首次设置地址 |
| `unhealthy` | danger | 运行异常：服务进程在运行或服务可连接，但未通过就绪检查 |
| `failed` | danger | 启动失败：启动流程结束后没有服务在运行 |

## 桌面壳结构

- 默认窗口为 `1280×720` 逻辑像素，最小窗口为 `960×560`；创建窗口时根据屏幕工作区与最小尺寸约束调整大小。
- 顶部拖动区高度为 `44px` 且透明，直接位于画布上；顶部放置共享黑白人物标识、窗口标题与窗口控制，不放置页面主操作。
- 窗口使用 `184px` 导航列与单一主内容区，宽度不超过 `1100px` 时导航列为 `156px`。导航栏是列内悬浮在画布上的表面盒子，导航项由功能图标、可见文字和可访问名称组成，当前项位于带抬升阴影的选中胶囊上；底部是服务状态圆点与主题入口。
- 运行状态、环境检查、日志诊断、偏好设置和关于应用保持稳定分区，切换时保留当前任务上下文。
- 主内容区优先使用单列任务流；只有状态与操作真实并行时才使用双列。
- 日志与路径使用等宽字体，保持可选择、可复制和可横向查看。
- 文本选区使用浏览器和操作系统的默认高亮，不通过 `::selection` 覆盖选区背景或文字颜色；控件选中态独立使用组件主题。
- 主要任务区使用明确的分组，次级信息通过数据行、分隔线和留白组织。五个工作区的内容分组都是画布上以阴影抬升的表面盒子。
- 环境检查顶部以状态图标、结论和检查计数概括结果；阻塞与警告项始终展开，正常项按安装与配置、运行环境分组收起，平台、RayleaBot 版本、安装目录与管理界面地址列在末尾的环境信息分组。启动服务时自动准备的用户配置、Chromium 与 FFmpeg 按正常项展示，不计入警告。
- 尚未取得检查结果时显示“尚未检查”；发生本地错误且无检查结果时显示“检查结果不可用”及重新检查入口，不给出可以启动的结论。
- 偏好设置在页头下方用页签分为路径、关闭窗口与维护三栏，切换页签不丢弃路径草稿。路径栏的阅读态使用定义行，编辑、放弃与保存位于栏顶右侧，输入框与路径选择只在编辑态出现，草稿期间页头显示“草稿编辑中”。关闭窗口栏以三张并排的选项卡片列出关闭方式，选中即单独保存并立即生效，不随路径草稿提交，也不打断进行中的服务启动；保存失败时恢复原选项并在卡片下方说明原因。维护栏列出重置管理员账号与退出启动器。
- 日志诊断顶部是服务状态、日志状态和管理界面地址的概览条；实际异常输出完整展开并优先显示，打开日志目录位于日志分组内，技术快照默认收起并在自身区域横向滚动，页面只有一个纵向滚动区。服务由其他进程启动时，启动器没有捕获它的输出，页面引导到管理界面的实时日志，不显示为无异常。
- 运行状态页顶部以状态透镜、状态名和说明呈现正式状态，右侧操作按钮排成一行并保持内容宽度，主操作位于最右侧：服务运行时依次为停止、重启与管理界面，未运行时主操作为启动。由其他进程启动的服务不能由 Launcher 重启，重启按钮保持禁用并在按钮下方说明原因；重启进行中按钮行保持运行时的布局。页头只保留页面标题、进行中的操作和刷新入口。运行详情是带功能图标的定义行分组，没有新的异常输出时收为单行摘要；环境问题与运行环境准备位于右侧关注栏，窗口宽度不超过 `1050px` 时移到主列之后。运行环境准备列出服务就绪检查报告的待准备资源，入口打开管理界面。页面不用装饰性指标填充留白。

## 组件映射

| 场景 | 组件 | 规则 |
| --- | --- | --- |
| 主操作 | `LauncherButton emphasis="prominent"` | 当前工作流保持唯一，使用品牌填充的胶囊与白色 `700` 字重文字 |
| 人工确认 | 确认对话框的确认按钮 + attention token | 只用于需要明确判断的动作，不与警告色混用；确认按钮使用人工关注色填充 |
| 危险操作 | `LauncherButton` + danger token | 停止、重置和完全退出，必须有明确结果文案；工作区使用危险色文字的次级胶囊，确认对话框中的确认按钮使用危险色填充 |
| 次级与工具操作 | `LauncherButton` | 使用与所在容器明暗相反的控件填充和抬升阴影，不加边框，不与主操作竞争；侧栏主题入口是透明的圆形工具按钮 |
| 文本输入 | 原生 `input` | 完整标签、清晰焦点和禁用状态；始终使用抬升表面与控件边界 |
| 页签 | Reka `Tabs` | 偏好设置的分栏；自动激活并支持方向键，标签前带中性图标，选中项使用品牌前景色文字与 `2px` 底线 |
| 单项选择 | Reka `RadioGroup` | 关闭方式等互斥设置；选项为抬升的卡片，选中项使用品牌柔和底与品牌填充的勾选圆标，未选项显示控件边界的空心圆 |
| 复选 | Reka `Checkbox` | 关闭确认中的“记住本次选择” |
| 菜单 | Reka `DropdownMenu` | 主题入口的单选菜单 |
| 进度 | Reka `Progress` | 运行环境准备；未知进度显示往返移动的短条 |
| 状态 | 状态胶囊与说明条 | 同时提供文字、图标或结构化标签 |
| 确认 | Reka `Dialog`（`LauncherDialog`） | 仅用于破坏性或不可在原位安全完成的决定 |

Reka UI 提供无样式的交互原语，负责焦点约束、键盘操作与 ARIA 语义；外观全部由 `surfaces.css` 与主题 token 定义。按钮统一使用 `LauncherButton`，页面不另建同类控件。

功能图标统一使用 Lucide 线性图标，默认 `20px`、`1.75` 线宽；状态透镜内的状态符号加粗为 `2.5` 线宽。界面人物标识用于应用身份，浅色主题使用原版，暗色主题将填充与描边整体反色，保留母版曲线、手势与透明背景；功能图标用于导航、状态与操作，两者不互相替代。

## 密度与层次

- 桌面控件高度为 `36px`，导航与关键操作目标至少为 `40px`；触控或粗指针场景提升到 `44px`。
- 页面间距使用项目级 `4/8/12/16/24/32px` 标尺，导航、字段和面板按任务关系选择不同节奏。
- 圆角标尺为 `4/6/8/12/999px`；标准控件使用 `8px`，任务表面和浮层使用 `12px`。侧栏、内容分组、Dialog、菜单、文本输入与胶囊按钮使用局部圆角，见 [表面与层次](#表面与层次)。
- 每个盒子只声明一种层次：以柔和阴影抬升，不同时叠加边框；盒子内的数据行以 `1px` 细分隔线组织。
- 普通说明与字段不包裹为卡片；状态摘要不使用 hero 指标模板。
- 选中导航使用完整的选中胶囊、`700` 字重文字和品牌前景色功能图标，不使用内嵌彩色侧边条。
- 工作区页面标题为 `24px`，环境检查结论与关于应用中的应用名为 `20px`；组标题为 `16px`，正文为 `14px`，任务标签、路径和日志为 `13px`。`12px` 用于窗口 chrome 与辅助元数据；运行状态主值使用 `30px`、`700` 字重和 `1.2` 行高。
- 界面字体只提供 `400`、`500`、`700` 三个字重：页面、分组与对话框标题、状态主值和主操作使用 `700`，数据标签、列表项标题、状态标签和次级按钮使用 `500`，正文使用 `400`。数字、时间与路径使用等宽数字。
- 品牌、标题、正文与控件统一使用共享的 HarmonyOS Sans SC（`--font-sans`）。三个未经修改的 TTF 与许可协议随 Launcher 构建打包，“关于”页声明使用了该字体。
- Vite 开发服务器仅对 Launcher 与共享设计目录开放文件访问，界面字体位于 `design/fonts/`；开发与生产均须实际加载声明的界面字体。

## 动效与反馈

- 控件反馈采用 `100–160ms` 短节奏，工作区采用 `180–220ms`，浮层采用 `200–220ms`；当前控件状态为 `160ms`，工作区切换为 `220ms`，Dialog 进入为 `220ms`、退出为 `160ms`，主题切换为 `420ms`，跟随系统自动切换为 `280ms`。主题菜单进入为 `220ms`，关闭时立即消失。
- 控件、Dialog 和主题动效使用 `cubic-bezier(0.16, 1, 0.3, 1)`，只表达状态、反馈、载入和内容显隐。
- 除主题菜单的 CSS 进入动画外，动效由 Motion for Vue 驱动。工作区使用 `220ms` 可取消的淡入，采用 `cubic-bezier(0.25, 0.1, 0.25, 1)`，从 `0.88` 不透明度过渡到完全不透明且不位移；状态与页面内容在点击时立即替换，导航在动画期间持续可交互。Dialog 的进入和退出由 Motion 负责：表面在透明度与 `0.96` 缩放间过渡、遮罩只淡化，退出完成后才卸载内容并释放焦点约束。主题切换由 Motion 驱动 View Transition 新快照的 `clip-path`。连续操作取消旧动画并从当前状态继续，不使用计时器推断完成状态。
- 服务状态变化时，状态圆点底色以 `200ms` 过渡，状态图标在缩放与淡化中替换；启动中与停止中的同步图标每 `1.4s` 匀速旋转一周，表示操作仍在进行。状态名与说明在原位交叉淡化并伴随 `4px` 位移；交叉淡化的文字对辅助技术隐藏，辅助技术读取同一位置的纯文字状态。
- 可展开区域由 Motion 在 `220ms` 内展开高度并淡入内容，收起为 `160ms`；`details` 在收起结束后才关闭，折叠时内容仍保留在文档中，折叠箭头随展开状态旋转。
- 侧栏选中胶囊是位于图标与文字之下的独立层，点击导航项时从上一项所在位置由 Motion 以弹簧滑到新导航项。起点在点击时读取，不使用共享布局动画：布局投影会在侧栏每次渲染时读取页面滚动位置并强制同步重排。非点击的切换与减少动态效果时直接出现，强制颜色模式下隐藏这一层，由系统高亮色标记当前项。
- View Transition 不可用时立即替换主题，功能与焦点顺序保持完整。同一元素不叠加 View Transition、Motion 和 CSS 动画。
- 悬停不平移或缩放面板和按钮；按钮与对话框选项按下时换用按下填充并收起抬升阴影，不缩放。日志追加不逐条播放进入动画。
- `prefers-reduced-motion` 或 forced-colors 下关闭非必要动画，进度与忙碌状态保留静态文字或图标。动效时长不代表帧率或性能承诺。
- 减少动态效果分别作用于 Motion 动效、主题菜单、工作区和进度反馈，不依赖全局极短动画时长覆盖；未知进度保留进行中的文字和无障碍状态。

## 表面与层次

Launcher 与 Web 管理面使用同一套表面规则：窗口是画布，盒子是表面色，控件与所在容器明暗相反。规则由 [`surfaces.css`](../../launcher/src/renderer/src/surfaces.css) 实现，颜色与阴影全部来自主题 token：`canvas`、`surface`、`surface-raised`、`surface-soft` 与 `--shadow-surface`、`--shadow-raised`、`--shadow-floating` 三层阴影，不新增共享 token。

- 窗口背景是画布：浅色主题为纯白，暗色主题为炭黑，不使用渐变、图片、背景模糊、高光或内发光。Windows 与 macOS 宿主先绘制同色画布；Linux 保持原生底层透明，由 Renderer 绘制不透明画布、`8px` 窗口圆角和 `1px` 中性外边框，圆角之外透出桌面。最大化时移除圆角与外边框；切换主题时保持原生底层透明。
- 侧栏、内容分组、Dialog 与主题菜单等盒子使用表面色，不加边框，只以阴影表达层次：页面内的盒子使用 `--shadow-surface`，Dialog 与菜单使用 `--shadow-floating`。
- 控件取所在容器的相反明暗：位于画布上的次级按钮使用表面色，位于盒子内的同一按钮使用抬升表面色，两者都以 `--shadow-raised` 抬升、不加边框。`:root` 把继承变量 `--control-fill` 声明为表面色，每个盒子把它重新声明为抬升表面色，按钮、对话框选项、偏好设置的选项卡片与状态透镜的圆底统一读取该变量。悬停时画布上的控件换为柔和表面色，盒子内的控件叠加少量文字色；按下时换为更深的按下填充并收起阴影。
- 文本输入始终使用抬升表面与 `1px` 控件边界；聚焦时边框改为焦点色并叠加 `1px` 内侧描边，不向外扩张。禁用的输入使用柔和表面与普通边界。
- 每个视图只有一个突出的主操作：品牌填充的胶囊与白色 `700` 字重文字，悬停与按下使用对应的品牌填充变体。禁用的主操作按次级按钮呈现。
- 选中导航是带 `--shadow-raised` 的选中色胶囊，文字为 `700` 字重、图标使用品牌前景色；悬停使用导航悬停色。
- 盒子内的数据行、检查项、字段与操作行之间使用 `1px` 边界色细分隔线，沿用行的内缩，不贯穿盒子。日志、技术快照与中性图标底是柔和表面色的凹槽。
- 状态用柔和底色的图标圆底（例如成功柔色底上的成功色符号）和带图标或标签的状态色文字表达，不单独依赖颜色；关注面板、处理方式与说明条使用对应的柔和底色，不加边框。
- 状态透镜是控件填充色的圆底，以 `--shadow-raised` 抬升，中间是状态色实心圆点与状态符号。浅色主题的状态符号为白色；暗色主题的状态色较浅，符号改用画布色，进行中的品牌色圆点仍用白色符号，保证图形对比度达到 `3:1`。侧栏底部以不带圆底的紧凑状态圆点显示同一状态与符号。
- 圆角：侧栏 `24px`，内容分组 `20px`，Dialog `24px`，主题菜单 `16px`、菜单项 `10px`，文本输入 `10px`，按钮与导航项为胶囊，状态透镜为圆形。胶囊按钮、对话框选项、选项卡片与主题按钮以 `2px` 焦点色外侧轮廓（偏移 `2px`）显示键盘焦点，导航项、页签与窗口控制使用内侧轮廓；禁用按钮保留填充、收起阴影并使用弱化文字。
- 五个工作区共用同一构成：页头与内容直接位于画布上，组标题位于分组之外，分组内用带功能图标的数据行、细分隔和可展开行组织。内容列宽为运行状态与日志诊断 `1120px`、环境检查与偏好设置 `960px`、关于应用 `800px`。
- forced-colors 下盒子、按钮、状态透镜与浮层改用系统颜色与 `1px` 边界并去掉阴影，选中导航使用系统高亮色。

## 浮层

- Dialog 是画布上方的表面盒子：`24px` 圆角，无边框，以 `--shadow-floating` 抬升，不模糊背后的窗口。遮罩是纯色压暗，浅色主题为 `rgb(0 0 0 / 28%)`，暗色主题为 `rgb(0 0 0 / 50%)`。Reka 把 Dialog 与菜单挂载在文档末尾；主题变量定义在根元素上，浮层与页面使用同一主题。
- Dialog 标题使用 `48px` 小号状态透镜：重置管理员账号为危险色，关闭启动器与其他待确认操作为人工关注色。选项卡片与按钮是盒子内的控件，使用抬升表面与 `--shadow-raised`；确认按钮按危险或人工关注填充，是 Dialog 中唯一的填充操作。
- 主题菜单是 `16px` 圆角的表面盒子，以 `--shadow-floating` 抬升；菜单项是 `10px` 圆角的行，悬停显示导航悬停色，当前主题由品牌前景色的勾选标记表示。
- 选中背景和文字使用中性色，浮层不改变状态或操作语义。

## 原生图标与打包

- [`design/mark.json`](../../design/mark.json) 是黑白人物标识的矢量母版；[`scripts/generate-launcher-icons.mjs`](../../scripts/generate-launcher-icons.mjs) 读取原版路径、黑白填充与白色细轮廓，用 Launcher 工作区安装的 Skia 后端 Canvas 2D 包 `@napi-rs/canvas` 光栅渲染 [`launcher/assets/`](../../launcher/assets/) 中的应用 PNG、亮暗托盘 PNG 与 Windows ICO。暗色托盘版同步反转填充与描边，几何与透明背景保持不变；生成不依赖主题 token、SVG 来源文件、浏览器或 Wails CLI。
- 应用 PNG 为 `1024×1024`，固定使用白发原版；`tray.png` 与 `tray-dark.png` 均为 `32×32`，分别使用原版与用户确认的整体反色版。母版路径经 `Path2D` 直接绘制，产物字节只取决于输入与 `@napi-rs/canvas` 版本。标识来自经用户确认的 AI 辅助人物概念图，再转为贝塞尔矢量；PNG 内嵌对应来源及确定性渲染元数据。
- Windows ICO 包含 `16/24/32/48/64/128/256px` 七种尺寸，每种尺寸按目标像素独立渲染，Windows EXE 与应用文件图标固定使用原版。Go 宿主通过 Wails 的 `SetIcon` 与 `SetDarkModeIcon` 提供两种托盘 PNG，由系统托盘主题选择；Launcher 界面标识则跟随应用的有效主题。
- Windows 资源由 [`generate-windows-resources.mjs`](../../launcher/scripts/generate-windows-resources.mjs) 使用冻结的 Wails `v3.0.0-beta.9` 生成对应架构的 `rsrc_windows_<arch>.syso`；根目录开发启动、Launcher 独立开发与打包均在 Go 编译前调用。缓存核对 ICO、Windows manifest、Go 模块、生成器输入及产物，资源缺失或漂移时重新生成；Windows manifest 使用 `asInvoker` 普通用户权限。
- 更新原生图标后需重新构建并启动 Launcher，由新进程载入窗口、托盘和 EXE 图标资源。
- 在仓库根目录运行 `node scripts/generate-launcher-icons.mjs --check` 校验来源与资产摘要。在 Windows 上运行 `go run ./tools/cmd/verify-windows-icon-resources`，验证默认打包 EXE 中的七尺寸图像负载与源 ICO 逐字节一致；其他产物通过 `--exe <path>` 指定。资源校验与实际窗口、任务栏、托盘显示检查分别承担不同验证职责。

## 小窗口策略

- 界面验证使用 `1920×1080` 屏幕上的默认 `1280×720`（16:9）窗口；低于 `1920×1080` 的屏幕不在支持范围内。
- Launcher 最小窗口为 `960×560` 逻辑像素，所有工作区、Dialog 与窗口控制在该尺寸下保持可操作且布局不破损；该尺寸只是布局下限，不作为验证目标。
- 最小宽度等于 `1920×1080` 屏幕在 100% 缩放下的半屏宽度，窗口可以与其他应用左右分屏；最小高度仍能放进该屏幕在 175% 缩放下约 `570px` 高的工作区，放大显示时窗口不会超出屏幕。
- WebView 不开放页面缩放，任何窗口尺寸都保留左侧导航盒子与单一主工作区，不切换为顶部导航。
- 标题操作、表单和日志按优先级换行或滚动，不截断关键标识符。
- Renderer 根节点不依赖隐藏溢出裁切内容；横向滚动只出现在日志、技术快照或不可安全换行的标识符区域。
- 最小窗口仍保留启动、停止、预检、设置、恢复入口和打开 Web 管理面的完整能力。

## 验收条件

- `system`、`light` 和 `dark` 三种偏好均同步作用于 CSS variables 和窗口背景。
- 主操作、人工关注、警告和危险具有独立且稳定的语义。
- 界面符合 [`DESIGN.md`](../../DESIGN.md) 的 Do's and Don'ts，不使用装饰性循环动效；画布、盒子、控件与浮层不使用渐变、背景模糊或半透明材质，层次只由表面色与阴影表达。
- 键盘顺序、焦点、对比度、状态标签、reduced-motion 和 forced-colors 达到 WCAG 2.2 AA。
- Launcher 继续只负责本机进程、系统集成、更新确认和打开 Web，不复制管理面业务。

# RayleaBot Plugin Management Surface

本规范定义插件包内管理页与 Web 宿主工作区之间的边界。宿主工作区的视觉语义以根目录 [`DESIGN.md`](../../DESIGN.md) 为准；插件页面能力、静态资源与同源管理 API 调用以 [`Plugin Management UI`](../plugin/management-ui.md) 与正式 contracts 为准。

## 适用范围

- 宿主工作区（页面标题、页签、可信代码确认、加载、错误、重试和退出）遵循 `DESIGN.md`。
- 插件页面的视觉与交互体系由各插件仓库自行维护，官方插件与第三方插件同样如此；宿主不规定插件页面的配色、字体、密度、组件形态或页面组织。官方游戏插件参照对应游戏的官方视觉语言建立自己的设计记录，例如星铁插件在其仓库的 `ui/DESIGN.md` 中维护。
- 宿主只对插件页面提出下文的技术边界与无障碍要求。

## 技术边界

- 运行期页面的 HTML、CSS、JavaScript 和字体只读取插件包内的静态产物，不加载宿主组件运行时或全局 store；图片与音视频可以来自 HTTPS 来源，例如 QQ 头像。
- 页面不得假设宿主 CSS custom properties、字体资源或框架组件可用；`@rayleabot/plugin-ui` 提供的宿主亮暗模式与主题变量是可选输入，页面可以采用、映射或忽略。
- 页面业务交互只使用受保护的管理接口，不增加视觉专用旁路。
- 页面不在内容内重复宿主标题、插件名称、信任提示或全局导航。
- 敏感值字段不得在提示、示例、日志或视觉测试数据中包含真实凭据。

## 宿主工作区

- 宿主标题和页签使用 Web 管理面的标准组件与密度。
- iframe 外围使用中性边界和项目级表面，不使用彩色侧边条、背景模糊或多层卡片。
- 宿主菜单与确认浮层沿用 Web 产品浮层的不透明表面。
- 加载状态使用与页面工作区一致的骨架；失败状态说明原因、重试操作和返回插件详情的入口。
- 未验证来源确认使用人工关注语义，危险或失败状态继续使用正式语义色。
- 宿主品牌与标题使用共享人物标识和随包的 HarmonyOS Sans SC；标识按宿主有效主题选择浅色黑白版或独立暗色灰阶版，两版均保留白发、手势与透明背景；粗指针环境下启停开关与相邻操作使用至少 `44px` 触控目标。
- 宿主标题、设置分组、保存反馈、启停及相邻工具保持紧凑对齐；页面加载、空数据、失败、未保存和保存生效具有可区分的文字状态。
- 宿主不向 iframe 注入样式，也不把自身字体视为 iframe 已有资源。

## 无障碍与通用要求

以下要求适用于所有插件页面，与页面采用的视觉体系无关：

- 以 WCAG 2.2 AA 为验收目标：文字、控件、焦点和状态满足对比度要求，正文至少 `4.5:1`，焦点轮廓与相邻背景至少 `3:1`；颜色不得成为唯一信息。
- 所有正式操作可通过键盘完成，焦点顺序与视觉顺序一致，焦点持续可见。
- 错误与保存结果关联到对应字段或操作，并同时提供文字信息。
- `prefers-reduced-motion` 下移除非必要过渡；轮询和任务进度仍提供静态状态文本。`forced-colors` 或背景模糊不可用时保持可读与可操作。
- 粗指针环境保持设置、保存、删除、触发和返回宿主的完整能力，交互目标不小于 `44px`。

## 验收条件

- 插件页面满足上述技术边界与无障碍要求。
- 宿主加载、错误、可信确认和 iframe 边界符合 Web 界面规范；宿主浮层使用不透明表面。
- 本规范不改变插件 manifest、静态资源路由、CSP 或管理 API。

# 日志与发送结果

默认日志保留逐条消息收发、重要状态变化和真实失败。无变化的后台轮询使用 DEBUG；同类后台故障记录首条，每五分钟汇总次数，确认恢复后记录恢复。日志聚合不改变调度结果统计。

日志正文面向日常运维，说明对象、结果和必要的处理办法。例如“插件订阅与解析已启动”“连接已断开，正在重连”。收到消息直接显示消息摘要，不附加内部排队过程；插件目录、任务 ID、耗时、协议错误码等诊断信息放在结构化详情中。备份位置、配置错误所在文件等有助于操作的路径仍可显示在正文。

插件扫描明细、启动进度、缓存命中和请求诊断使用 DEBUG；默认级别保留启动结果和配置状态变化。一次操作的进度与结果不重复记录为 INFO。重复的后台故障由汇总日志报告，来源请求的逐次诊断使用 DEBUG；恢复与检查结果合并记录。插件业务结果与调度统计由执行流程记录，历史日志保留事件发生时的记录。

异步任务通过管理日志呈现等待、执行和完成状态。正文直接说明操作与对象，例如“安装插件‘三角洲助手’（执行中）”；任务类型代码与安装来源路径放在详情中，不重复拼接“任务执行中 plugin.install”等前缀。任务进度数值变化不重复写日志。

插件在内部请求未完成时关闭通信或退出，由 Runtime 记录一次带插件 ID 和错误码的 WARN；退出码为 0 也不能代表请求已经完成。分发和调度层在收到 Runtime 已记录故障的标记后省略重复告警。

“内部事件未完成”表示 Server 与插件的事件处理未完成，不能据此认定 QQ 消息发送失败。发送请求发出后未取得确定回执时使用 `adapter.send_unconfirmed`，消息可能仍会送达；系统不自动重发。

停用插件会等待当前初始化或重载操作结束，再使用 5 秒停止预算。Server 关闭时取消已接收的投递，在关闭期限内停止插件进程，然后等待任务结果写入完成；尚未开始的定时事件按取消计入 `other`。

开发日志按职责分别保存在 `logs/dev/server/`、`logs/dev/web/`、`logs/dev/launcher/` 和 `logs/dev/build/`。`logs/dev/start/` 保存进程编排、构建结果与子日志位置。插件 stderr 按完整行脱敏；超长诊断行会被省略。

首次设置地址只向需要初始化的交互终端显示，管道与日志文件不能接收 setup 凭据。管理日志与诊断详情不能包含 token、Cookie 或密码。

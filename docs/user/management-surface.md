# Management Surface

本页说明 RayleaBot 当前正式提供的管理入口、页面职责和跨页查看路径。

## 当前正式入口

| 入口 | 作用 |
| --- | --- |
| Web 管理面 | 在线管理主入口 |
| Launcher | 桌面启动、停机、本地预检和打开管理面 |
| CLI | 本地离线恢复与诊断入口 |

常规插件管理、状态查看、日志查询和配置编辑以 Web 管理面为主。服务端是正式状态来源，Launcher 负责桌面壳交互与本地进程编排。

## Web 管理面页面

| 页面 | 路由 | 作用 |
| --- | --- | --- |
| 系统状态 | `/` | 查看健康、就绪、聚合诊断、恢复摘要、近期变化、系统工具和正式更新状态 |
| 内置菜单 | `/menu-center` | 查看平台内置菜单、声明命令和当前可用菜单入口 |
| 插件列表 | `/plugins` | 安装、卸载、启用、禁用、重载和查看插件列表 |
| 插件商店 | `/plugins/store` | 浏览商店目录、查看来源与信任信息并进入插件安装确认 |
| 全局插件设置 | `/plugins/settings` | 查看和保存命令前缀、插件日志和插件存储设置 |
| 插件详情 | `/plugins/:id` | 查看 rich manifest metadata、声明能力、命令、实时输出和插件内置管理页 |
| 权限策略 | `/permission-policy` | 查看和保存超级管理员和默认权限 |
| 黑白名单 | `/access-lists` | 管理白名单、黑名单和白名单启用状态 |
| 限流中心 | `/rate-limits` | 查看和保存用户命令、群命令、插件消息、目标消息限流和冷却提示 |
| 指令中心 | `/commands` | 查看当前生效命令策略和全部声明命令 |
| 任务调度 | `/scheduler` | 查看插件声明的定时任务、运行状态与耗时，手动触发并查看执行日志 |
| 实时日志 | `/logs` | 查看当前服务启动窗口内的日志、命令策略拒绝记录和增量更新 |
| 历史日志 | `/logs/history` | 查看按时间范围筛选的历史日志和命令策略拒绝记录 |
| 协议中心 | `/protocols` | 管理已配置连接，通过弹窗新增、编辑连接或查看兼容矩阵 |
| 配置 | `/config` | 查看和保存通用配置 |
| 模板预览 | `/render/templates/:templateId?` | 查看模板信息、输入结构和同步 HTML 预览结果 |

## 权限策略页

- `/permission-policy` 提供超级管理员和默认权限级别配置。
- 超级管理员填写 OneBot11 QQ 账号，跨 OneBot 连接生效并跳过黑白名单与冷却拦截；QQ 官方 openid 不使用此列表。未单独声明权限的命令沿用默认级别。
- 页面仅在内容变化后允许保存，并显示未保存或已生效状态。

## 限流中心页

- `/rate-limits` 集中显示用户命令、群命令、插件消息和目标消息四类限流。
- 每项限流采用“次数、时间窗口、单位”的组合输入，页面同步显示可读预览。
- 冷却提示用于用户命令或群命令命中限流后的提示发送。
- 用户、群与外发目标的限流按协议、连接和机器人身份分别累计，同名目标不会跨连接共享额度。目标消息限流覆盖插件外发消息和平台冷却提示。
- 插件消息限流按插件累计外发消息次数，覆盖插件通过正式消息动作产生的发送与回复。

## 黑白名单页

- `/access-lists` 使用白名单和黑名单两个连续分区负责名单管理，每个分区显示当前条目数、筛选和操作。
- 白名单和黑名单列表都支持按“全部 / 用户 / 群”筛选、直接查看当前完整列表和单条移除。
- “添加条目”需要选择作用域、类型并填写目标 ID 和原因。OneBot 全局规则作用于所有 OneBot 连接；指定实例的规则还需填写连接标识与机器人 ID。QQ 官方 openid 必须使用实例作用域。
- 删除仅影响所选作用域内的条目，相同目标 ID 在其他实例的规则会保留。升级前的无作用域条目归入 OneBot 全局；旧 QQ 官方规则需要重新绑定实例与机器人。
- 列表中的目标 ID 支持点击复制，复制成功后会显示“已复制目标 ID”反馈。
- 白名单分区提供服务级启用开关，所有连接均受其约束。名单为空时启用会要求确认；启用后只有命中白名单的命令和 OneBot 超级管理员可通过准入检查，命令自身权限与冷却仍按各自规则执行。
- 白名单已启用且当前为空时，页面会持续显示“白名单已启用且当前为空”风险提示，提醒尽快补充条目或先关闭白名单。

## 页面联动

- 系统状态页的协议提醒和近期变化会提供到协议中心、日志中心和插件详情的入口。
- 系统状态页通过 `GET /api/update/status` 读取正式更新状态，通过 `POST /api/update/check` 触发受信发布元数据检查；Web 不下载或安装更新。
- 订阅中心插件详情页提供订阅状态、用户解析和立即检查入口。
- 协议中心首页展示已配置连接和运行状态。“添加连接”在弹窗中选择协议、填写配置，保存时才创建实例；取消不会写入配置。高级设置按需展开，包含连接标识、QQ 沙箱环境或所有连接共用的重连策略。
- `/protocols?adapter={id}` 打开指定连接的配置弹窗，`/protocols?view=compatibility` 打开兼容矩阵。旧的 `/protocols/onebot11/{id}`、`/protocols/qqofficial/{id}` 和 `/protocols/compatibility` 地址会转到对应弹窗，共用协议中心页签。
- 连接弹窗中的运行状态与诊断入口可进入实时日志，自动带上当前协议的筛选。每个实例展示自己的正式运行摘要，OneBot 实例同时展示各自的详细传输快照。
- 权限策略承担超级管理员和默认权限配置；黑白名单承担名单条目和白名单启用状态；限流中心承担命令与外发消息限流及冷却提示配置。
- 插件中心侧栏包含插件列表、插件商店、全局插件设置、菜单中心、指令中心和已安装插件。每个插件都能独立展开概览和 manifest 声明的内置管理页，展开或收起一个插件不会改变其他插件；当前页面对应的插件会自动展开，返回主导航时页面保持不变。
- 已打开的插件保留各自工作区页面，从侧栏再次选择时恢复该页面；关闭插件工作区后，再次选择该插件进入概览。
- 插件列表使用响应式卡片网格，并在移动端提供筛选抽屉。插件名称进入概览，“管理”按钮进入插件声明的首个内置管理页；未声明管理页时显示概览。
- 指令中心支持 `plugin_id` 过滤，命令表中的插件列可直接进入插件详情。
- 插件详情提供当前插件的指令中心入口、历史日志入口，以及同一页内的插件管理页工作区切换。
- 实时日志与历史日志支持 `level`、`source`、`protocol`、`plugin_id`、`request_id` 和 `log_id` 工作区 query；`level` 与 `plugin_id` 可重复传入多个值，历史日志额外支持 `start_at` 与 `end_at`。
- 日志页常驻级别与来源筛选，协议、插件和请求 ID 位于“更多筛选”；两个日志路由共享相同的筛选与详情结构。
- 命令被白名单、黑名单、权限或冷却拒绝时，日志中心会显示拒绝摘要，日志详情会显示 `command_name`、`error_code`、`reason`、`policy_stage` 和匹配插件列表。
- 日志详情会根据稳定字段提供插件详情、协议中心和请求 ID 对应日志页入口；异步任务日志使用 `source=tasks`。
- 模板预览页的结果区显示当前模板的同步 HTML 预览结果。
- 模板目录按插件名称分组，优先显示模板名称，可搜索插件、模板名或标识。效果预览、示例数据和模板说明分别展示；修改示例数据只影响当前预览，可恢复默认示例。刷新目录会移除已失效的条目，内部标识和版本放在模板说明中按需查看。

## 插件内置管理页

- 插件在 manifest 中声明 `management_ui.pages` 后，插件中心侧栏会显示对应内置管理页入口；侧栏折叠或使用移动端时，详情页内的切换控件提供相同入口。
- 管理页静态资源通过插件专属 origin 公共只读提供；该 origin 不接收管理 cookie、没有 `/api`、没有管理端 CORS，并应用严格 CSP。
- iframe 通过 bridge v3 的 nonce-bound `MessageChannel` 请求宿主读取或保存设置；插件页面不能直接调用受保护接口。
- 密钥界面只显示是否已配置，允许覆盖写入与显式删除，从不读取或回显已有明文。
- 未验证来源插件首次打开内置管理页时需要手动确认；插件版本或来源变化后会重新确认。
- 插件管理页读取和保存插件设置；插件管理动作通过 `POST /api/plugins/{plugin_id}/management/actions` 转给插件 runtime 处理。
- 插件安装前会展示来源、目标平台、后端摘要、UI 状态、artifact 校验结果和能力；操作者必须明确确认第三方 Go 后端会作为完全可信的本地代码运行。

## 配置工作台

`/config` 按六个分类组织通用配置。先选择分类，再调整常用参数；浏览器、队列、会话等高级参数在当前分类内展开。窄屏通过上方的分类选择器切换，搜索框可以按配置名称、说明或字段路径查找，包括折叠区内的参数。默认值显示为输入框为空时的占位文本（placeholder）；它仅提供提示，不会自动填入或提交。

各分类共用一份草稿，切换分类与搜索不会丢失输入；尚未填完整的限流参数也会保留，保存前需补齐。右下方的保存浮标在未修改时保持中性，有修改时变为暖色并显示未保存项数，点击可一次提交所有分类的修改。保存浮标左侧的“撤销修改”按钮恢复最近收到的配置。离开页面前可以选择继续编辑或放弃修改。保存期间显示加载图标，失败时草稿保留并提示重试，成功后恢复中性；悬停或聚焦浮标可查看状态，需要重启才能生效的结果也会通过保存通知说明。

## 状态来源与 Launcher 管理入口

- Web 与 Launcher 都直接访问服务端管理接口。
- Web 使用正式 HTTP API 与管理 WebSocket 读取状态和提交操作。
- Launcher 使用 `healthz`、`readyz`、`/api/setup/status` 和 `/api/launcher/status` 检查本机服务连接，并把这些正式结果与本地进程状态一起展示。
- Launcher 打开 Web 时只打开管理面 URL；Web 管理面通过初始化和登录接口建立会话。
- 未登录状态打开 Web 深链时进入登录页；登录或初始化完成后返回目标页面。
- Launcher 停止本机服务使用 `/api/launcher/shutdown`。连接非本机服务时，Launcher 只做连接检查和打开 Web。

## 本地优先安全边界

- 管理入口默认监听 `127.0.0.1`，远程访问需要显式开启。
- Web API 和 WebSocket 都要求正式管理会话。
- Web 状态变更请求使用 HttpOnly cookie 会话，并校验 Origin 与 CSRF；本机 Launcher 控制接口另用 loopback 限制和 control token。
- 登录失败次数受限，避免暴力猜解管理员凭据。
- 远程访问场景优先通过 HTTPS 反向代理暴露，不开放无鉴权调试入口。
- 第三方插件不具备管理权限，插件能力与管理权限保持隔离。

| 暴露等级 | 典型场景 | 监听方式 | 初始化接口 | 风险提示 |
| --- | --- | --- | --- | --- |
| `localhost_only` | 默认本机部署 | `127.0.0.1` | 允许，仅本机 | 默认模式 |
| `lan_enabled` | 家庭或可信局域网 | 用户显式改为内网地址 | 默认禁止远程初始化 | 需提示已暴露到局域网 |
| `public_via_reverse_proxy` | 反向代理后公网访问 | 建议服务仍监听本地地址 | 禁止 | 需提示 HTTPS 与公网暴露风险 |

## 初始化与会话

已登录时，左下角“账号 → 修改账户”可修改管理员密码。输入当前密码、新密码与确认密码；需要修改用户名时展开“同时修改用户名”，留空则保留原用户名。新密码为 8–1024 个字符，前后空格会保留。保存成功后，所有设备的旧会话失效，使用新凭据重新登录。错误密码不会改动账户，验证尝试与登录共用失败次数限制。窄屏下从导航抽屉底部进入。

- 首次启动没有管理员账户时，服务进入 `setup_required`，仅开放本机初始化路径。
- 初始化完成前，不开放常规插件管理、配置修改和日志查询。
- 管理员凭据丢失时，正式恢复路径是停服后通过 Launcher 或 CLI 触发 `reset-admin`。
- 管理会话采用有限 TTL，可做滑动续期，但保留绝对有效期上限。
- 重置管理员凭据后，旧会话全部失效。
- 未登录访问受保护页面时，管理面进入初始化页或登录页，并在完成后回到目标页面。

## Launcher

- full artifact 统一以 Launcher 作为桌面入口。
- Launcher 负责启动、停止、重启服务、本地预检、打开管理面和版本提示。
- Launcher 本地预检关注安装根、`raylea-server` 路径、`config/user.yaml`、工作目录和启动器设置。
- 模板、浏览器和原生插件进程异常通过服务端 readiness 与系统 diagnostics 暴露；Launcher 组合这些正式结果和本地 preflight 展示启动状态。
- 启动时若本机已存在健康服务但不属于当前 Launcher 子进程，界面会标示“检测到现有服务”。
- 启动失败摘要来自健康探测、stderr 和日志尾部。
- 关闭窗口默认隐藏到托盘，不直接结束后台服务。
- 仅在用户明确选择完全退出时，Launcher 才触发优雅停机流程。
- Launcher 打开 Web 管理面时只打开普通 URL，管理会话由 Web 初始化和登录流程建立。

| 场景 | Web 管理面 | Launcher | CLI |

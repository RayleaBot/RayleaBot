# RayleaBot v0.6 多轮会话、优先级阻断与 KV TTL 执行计划

## 文档状态与范围

- 目标版本：v0.6；按用户于 2026-09-13 收窄后的范围执行。
- 范围：Core、Go SDK、仓库内示例、必要的 Web 声明展示、契约与文档。一工作项一提交。
- A0/A1/A3/B1/B2 已按原范围提交；新增 X1 精简阶段，后续工作以本文为准。
- 正式语义以 [contracts](../contracts/README.md) 为准；先同步契约和 fixtures，再实现对应能力。

## 一、交付目标

1. 插件登记下一条对话输入，用户回复不必重复命令前缀；SDK 提供回调式封装。
2. 消息插件按插件级优先级执行，同层并发，并可阻断后续层；保留跨层 FIFO。
3. 私有 KV 支持 TTL；过期值在读取、列表和逻辑配额中不可见。
4. SQLite 由 `000001` 事务迁移到 `000002`，旧备份恢复后首次启动迁移。

不增加用户取消命令、宿主业务 state、轮次版本号或总轮数上限、输入缓冲、通用关闭通知、显式替换参数、独立过滤阶段、NX、新配置键或阻塞式询问 API。不改造独立插件仓库，不发布 SDK 标签或要求从模块代理下载独立消费者。

## 二、对话会话

### 2.1 归属与状态

路由键包含 `source_protocol + source_adapter + bot_id + target.type + target.id`；`scope=user` 再包含 `actor.id`。默认 user；私聊按 user 处理。群级 conversation 与 user 等待可以共存，先匹配发送者的 user 等待。

宿主仅保存路由、对话 ID、具体插件进程归属、期限、通知选项，以及判断当前父事件所需的身份；业务步骤和草稿由插件内存或回调闭包维护，不传入或回显 state。

- 发起父事件完成前不接收回复；父事件成功终态后进入 waiting。
- 只有 waiting 接收下一条消息。选取与目标入队由短临界区协调，不增加独立的 claimed 状态。
- 输入开始处理后进入 handling；处理中或发起过程中到达的消息继续现有普通流程，不缓冲、不回放。
- 本轮调用 session.wait 时直接登记下一次等待，使用对话 ID 与当前父事件校验；不提供 revision、提案对象或提案幂等协议。本轮成功结束后恢复 waiting，没有再次登记则结束。
- 同一插件对同一路由键重新新建，直接覆盖自己的旧项；其他插件已占用该键时返回 plugin.session_conflict。
- 所有者按具体进程归属。停止、崩溃或重载时清理该进程全部对话；旧进程的迟到清理不能删除新进程登记的项。
- 适配器换号不主动关闭旧对话，完整路由键阻止串线，旧项等期限结束。名单拒绝只拒绝该消息，不主动关闭等待。
- 允许新建对话产生新的绝对期限；同 ID 再次等待仍受其原绝对期限约束。

### 2.2 协议

协议 v3、manifest v3 与配置 schema v4 保留。新能力插件声明 `min_core_version >= 0.6.0`。

| 动作或事件 | 形状与语义 |
| --- | --- |
| session.wait 新建 | 必须有父事件；data 可含 scope、timeout_seconds、notify_on_expire，均可省略；身份由当前消息推导 |
| session.wait 再次等待 | data 包含 session_id，可更新 timeout_seconds 和 notify_on_expire；只能由该对话当前消息事件发出 |
| 等待结果与 payload.session | session_id、scope、expires_at_ms；不含 state、revision、turn 或 max_turns |
| session.finish | data 为 session_id；所属进程可在任意活动事件结束自己的等待；未知、已结束或其他所有者返回 finished=false |
| session.expired | 可选超时通知，只投给仍存活的原所有者，payload.session 使用同一引用形状；没有关闭原因枚举 |

移除 plugin.session_stale。错误的当前父事件或无效等待参数使用已有参数错误；成功结束、覆盖和所有者停止不发送通知。超时通知走普通 target lane，遵循既有队列上限与发送能力，尽力投递。

### 2.3 SDK 与期限

SDK 提供 typed 登记/结束接口及回调式询问。回调映射和业务状态归 SDK/插件内存；挂起等待不占旧事件的并发许可，新输入使用新的 EventContext。旧父事件结束后继续拒绝其动作。

提示发送失败时调用有效父事件内的 finish 并释放本地续接；本地等待依宿主期限自行回收，不依赖超时通知到达。超时提示只能使用实际收到的新超时事件上下文发送。迟到回复不能误交给普通业务 Handler；回调异常由新请求的正常收尾处理。

期限与资源采用集中常量：单轮默认 60 秒、最大 600 秒，绝对存活 1800 秒，每插件最多 256 个、全局最多 1024 个活跃登记。超限拒绝；`now >= expires_at_ms` 即过期。没有总轮数限制、state 字节上限、缓冲上限或相应的新配置。

## 三、优先级与阻断

manifest 仅增加 priority（整数 -1000..1000，默认 0）与 block（默认 false）。管理面只读展示声明，不增加管理员覆盖配置。

- 普通消息按现有订阅选择候选，再按 priority 降序分层；同层并发。
- 命令消息保留声明者定向派发。额外选择 priority > 0 且订阅该消息的非声明者，先于命令声明者执行；每插件每消息只投递一次。
- 没有命令声明者时按既有普通订阅行为处理。
- 保留现行同名命令取最严格权限、白名单旁路、菜单处理和冷却语义，不拆分逐候选授权或增加一次性冷却计费。
- 对话输入保留名单准入；不从发起者复制权限给其他参与者。
- scheduler、管理动作、生命周期、身份广播与 webhook 保持已有投递方式。

成功终态显式 propagation=stop|continue 优先于静态 block；省略时使用 block。plugin.not_handled 正常继续；异常、超时与队列拒绝继续后续候选。传播字段只用于合法消息事件终态。

终态动作仍在现有 worker 调用内执行，发送完成后再推进层次；传播决定只看终态帧，发送失败不改写它。

### 跨层 FIFO

保留反例：A 的候选为 P→Q，B 只命中 Q；A 先接受，则 Q 必须保持 A→B。

在短 admission 临界区内按接受顺序为所有候选入队；低层项携带“上层已结束”信号，收到信号后才调用插件。不在高层完成后才追加低层队列项。停止传播、队列拒绝和运行时退出均释放相应等待，避免悬挂。

沿用每插件队列和事件处理超时；不增加整条消息总期限或全局传播容量。暂不要求 inactive 项释放执行名额，也不保留 A0 的循环依赖枚举检查。插件进程更换后不把旧队列项交给新进程。

## 四、KV TTL 与迁移

storage.kv set 增加整数 ttl_seconds，范围 1..31536000；省略时永久写入并清除旧期限。公开期限为 expires_at_ms，永久值省略期限。

- get 到期返回 exists=false，不返回 value 或 expiry；list 只列有效键并保留前缀转义与排序；delete 到期键不报告删除有效值。
- 键、值大小和现有全局逻辑配额仍在事务中验证；每个写事务捕获一次宿主时间。
- 不提供 if_not_exists 或 stored=false 语义。需要进程内条件写入时由插件自行同步。
- 清扫器随 App 生命周期每 60 秒分批删除到期行，每批 1000 行，使用期限索引；不另设每轮总行数或耗时预算。
- SDK 的 TTL 选项以 duration 表达：零表示省略，负数、正的非整秒和超上限拒绝，不截断。

000002 增加 expires_at_ms 可空列和非 NULL 期限索引；已有值迁移后永久有效。启动沿有序表在事务内迁移并更新版本，失败回滚，重复启动为空操作，未知版本拒绝。保留新建与迁移后 sqlite_master 的结构等价测试。

不生成迁移前副本。正式更新仍是停服备份、解压新版到独立目录、恢复、启动；旧目录和手动备份按现行说明保留。恢复接受 000001 与 000002，摘要保留真实源版本和目标版本；旧核心不能读取新结构。

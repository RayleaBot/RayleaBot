# Web 前端迁移执行计划 v1

状态：执行中，M0 技术验证已通过，正在建立基础组件。日期：2026-09-07。

实际版本、验证与性能对照见[实施记录](./design/web-ui-migration.md)。

迁移基准为 `612c5bc3`：协议中心已采用连接卡片、渐进式配置弹窗、统一工作区深链和固定中心的进入动画。该提交是试点功能与回归行为的对照点。

## 目标与完成条件

用 Reka UI、shadcn-vue 组件源码、Tailwind CSS 4 和 Motion for Vue 建立 RayleaBot 自有组件体系，替换 Web 管理面的 Ant Design Vue 与 Vben 风格对齐方案。保留 Vue 3、Vite、Vue Router、Pinia，以及已有请求、会话、实时数据和契约生成类型。

迁移完成必须同时满足：

- 页面壳、基础控件、浮层、状态反馈和正式工作区使用统一的产品组件与视觉规范。
- 交互原点、方向、进入与退出、快速反向操作、异步内容变化和减少动态效果模式均由产品组件明确控制。
- 保留协议中心和插件集合的独立对象卡片；表单、日志和数据表按任务组织，不以统一卡片墙替代所有页面。
- 原有配置保存、凭据脱敏、多实例隔离、重启提示、工作区恢复和错误处理行为通过回归验证。
- Web 运行时移除 Ant Design Vue 及其适配、全局覆盖样式和 Vben 视觉对齐实现；临时兼容路径清零。
- 新旧方案在同设备、同浏览器、同数据量下完成性能对照。不能以换库、静态截图或构建通过代替效果验证。

本计划定义迁移目标和执行顺序。当前已运行的版本线仍由[工程基线](./engineering/baseline.md)和[Web 工程基线](./engineering/web-admin-baseline.md)说明；每个迁移阶段落地时同步其实际状态，不提前宣称完成。

## 已确定的边界

| 层次 | 目标 | 迁移边界 |
| --- | --- | --- |
| 应用运行时 | Vue 3、Vite、TypeScript | 不迁移 React、Nuxt 或第二个前端应用 |
| 路由与状态 | Vue Router、Pinia | 复用现有 store、稳定 `viewKey`、query 和管理深链 |
| 基础交互 | Reka UI | 处理键盘、焦点、选择、弹层语义；在产品组件中配置默认行为 |
| 组件实现 | shadcn-vue 源码与项目封装 | 按需引入源码，审阅默认样式与依赖；业务页使用项目组件 |
| 视觉系统 | Tailwind CSS 4、CSS Variables、语义 token | 复用现有 token 生成链，重新设计 Web 的组件比例、层次与组合 |
| 动效 | Motion for Vue（`motion-v`） | 接管组件进入、退出和必要的布局变化；简单状态使用 CSS |
| 页面与主题切换 | 明确范围的 View Transition 与降级路径 | 同一元素的同一属性只有一个动画控制者 |
| 长列表 | 现有 TanStack Vue Virtual 与 `VirtualDataViewport` | 保留滚动锚点、自动跟随和测量逻辑；不为高频日志追加逐条动画 |
| 后端与插件通信 | 现行正式契约 | 不新增 HTTP client、WebSocket client、鉴权状态或主题协议 |
| Launcher 与插件页面 | 保持各自框架 | 本计划不重写 Launcher，也不批量迁移独立插件仓库 |

Router、HTTP、Pinia 与 Vite 不因使用新 UI 组件而升级现有冻结版本。Reka UI、`motion-v` 和 shadcn-vue CLI 的具体版本在 M0 通过兼容验证后锁定；CLI 的组件来源版本也要记录，不能依赖不固定的 `latest` 重生成。

不预装额外表格、表单或动画库。现有能力不足时，先说明具体组件风险，再选择一个补充实现。图标在 M0 清点，迁移最终只保留一套通用图标来源，品牌标识独立维护。

## 视觉决策

试点沿用现有青瓷品牌色与折叶标识。用户已要求开始执行；没有另行确认全面品牌重设，首批实现使用这一既有品牌基线。

重新设计布局、字体层次、控件比例、表面层次和动效。后续若用户选择全面品牌重设，再评估共享 token 与 Launcher 的影响；不将待选的新配色混入本次试点。

M0 的视觉交付应包含同一组真实任务下的主工作区、连接卡片、配置弹窗、选择器、错误状态和移动端结构。保留亮暗主题和键盘操作，不能仅展示一个美化的静态首页。

现有 [PRODUCT.md](../PRODUCT.md)、[DESIGN.md](../DESIGN.md)、[Web 设计映射](./design/web-management-ui.md)作为产品事实、品牌承诺与旧方案对照。重设计时同步旧组件、浮层材质、动效和布局约束；其中已经落后于正式契约的“单活跃 OneBot”等事实按当前协议与多实例实现校正，不能作为迁移限制。

## 实施阶段

### M0：建立视觉、兼容性和性能对照

工作：

1. 在基准提交之后建立独立迁移分支；只带入本任务相关内容，保留其他工作区改动。
2. 清点实际使用的基础控件、复杂表格、二维码、日期与时间输入、数字输入、菜单、拖动窗口、反馈和浮层，建立替换映射；缺少的组件能力先做最小验证。
3. 在隔离验证目录检查 Reka UI、`motion-v`、shadcn-vue CLI 与现有 Vue/Vite/Tailwind 的兼容性。记录版本、peer dependencies、源码来源、必要依赖和许可证信息。
4. 确认视觉方向，形成可运行的组件展示页及对应设计记录。该展示页只用于开发与测试，不加入正式管理菜单。
5. 记录现有代表页面的首屏资源、关键操作动画、主线程长任务、日志滚动及 iframe 场景。记录测试设备、浏览器、视口、数据量与采样方法。

交付：组件替换清单、锁定版本建议、设计与动效规范、性能对照记录。

退出条件：核心浮层、选择器、表单和虚拟列表没有未解决的能力缺口；视觉选择有明确结果；可以开始实现同一套基础组件。

### M1：建立产品组件与动效层

工作：

1. 在 `web/src/components/ui/` 按需引入并维护基础组件源码；使用现有 `components/` 组织 `AppDialog`、`AppConfirmDialog`、`AppDrawer`、`AppButton`、`AppSelect`、字段和反馈等产品封装。
2. 组件库的样式、位置、尺寸、关闭规则、焦点归还和动效默认值由产品封装统一决定。配置保存、权限判断和服务状态继续属于页面与 store。
3. 引入 `motion-v`，让 Motion 负责动画生命周期，Reka 负责交互语义；明确 Portal、离场保留、焦点锁定和卸载顺序，避免动画结束前丢失内容或结束后残留遮罩。
4. 将动效时长、曲线和尺度纳入现有 token/配置来源。简单悬停与按下仍可用 CSS，禁止同属性叠加多个动画实现。
5. shadcn-vue 生成结果先在隔离目录审阅，再导入需要的源码。不要让脚手架直接覆盖现有 Tailwind 入口、全局重置或设计 token。
6. 明确并同步迁移期工程基线。新旧组件只在迁移边界内短期共存，不能增加第二套路由、网络、业务状态或偏好系统。

交付：基础组件源码、组件状态展示页、集中动效配置、组件级交互验证。

退出条件：核心组件覆盖默认、悬停、焦点、按下、禁用、加载、错误、亮暗主题、窄屏和减少动态效果状态；组件具备后续页面所需能力。

### M2：完整迁移协议中心

工作：

- 保留已配置连接卡片和单一“添加连接”入口；取消新增不得产生实例。
- 使用新组件完成新增、编辑、确认和兼容矩阵弹窗；保留高级配置的渐进式披露。
- 保留 OneBot 四种传输、多传输组合、回连地址、独立令牌、QQ 凭据与事件选择。
- 保留新配置合并、同实例冲突提示、失败后草稿、双击防重入、凭据脱敏与重启反馈。
- 保留 query 驱动弹窗、旧链接重定向、单一工作区页签、日志入口和未保存离开保护。
- 试点可先运行在现有外壳中，但协议中心内部只使用新产品组件。临时开发入口在正式路径切换后删除。

交付：协议中心完整功能试点、桌面和窄屏效果、进入与退出动画证据、回归结果。

退出条件：达到下文交互验收要求，并完成真实操作路径下的视觉评审。需要用户判断的内容是具体可运行效果；配置语义和兼容性由测试与契约验证承担。

### M3：迁移应用壳、主题和公共入口

工作：

- 重做侧栏、页头、搜索、页签、面包屑、主题与密度偏好；保持 workspace 的身份和恢复语义。
- 替换顶层 provider、提示宿主及公共状态组件，审计浮层层级、嵌套弹窗、遮罩和滚动锁。
- 迁移登录、初始化、会话中断与凭据恢复指引的控件实现，保留正式 cookie/CSRF 登录、错误恢复与本机维护边界。
- 认证入口既有玻璃材质是否调整由视觉方案决定；管理表单和复杂配置浮层以实底可读性为默认，不沿用统一毛玻璃覆盖。
- 将现有页面动效接入统一策略，保证主题切换、浏览器历史导航与快速连续导航能够取消旧动画。

交付：新应用壳、共享主题映射、认证与反馈入口。

退出条件：键盘导航、工作区缓存、深链、会话过期、主题与密度持久化通过回归；iframe 与浮层在动画期间保持可达。

### M4：按业务工作区迁移剩余页面

| 批次 | 范围 | 关键回归 |
| --- | --- | --- |
| A | 插件列表、商店、设置、详情、菜单与指令中心 | 对象卡片、筛选、插件管理页、可信代码确认、任务与反馈 |
| B | 三方账号、权限策略、黑白名单、限流与通用配置 | 凭据保留、扫码流程、动态表单、错误提示、实际生效范围 |
| C | 系统状态、调度、实时日志、历史日志与模板预览 | 实时快照、虚拟滚动锚点、详情窗口、iframe、预览与诊断 |

每批替换其 Antd 组件、图标入口、局部样式和相应测试，批内完成后再推进下一批。公共组件缺口回到 M1 的组件层修正，不在单页复制第二份控件实现。

交付：每批可独立审阅的逻辑提交、对应功能与视觉回归记录。

退出条件：正式路由均已迁移，未迁移清单为空，不能因替换 UI 删除低频但正式支持的功能。

### M5：移除旧栈并完成交付验证

工作：

- 移除 Web 的 Antd 注册、provider、样式重置、主题映射、专用 vendor chunk 与遗留覆盖；清理不再使用的旧组件、图标依赖和迁移入口。
- 收敛 `motion/mini` 的既有调用及直接依赖，依实际调用和 `motion-v` 依赖关系处理；不以 lockfile 中仍出现 Motion 底层包判断迁移失败。
- 审查 shadcn 源码、依赖版本和更新方式，维护需要主动合并的上游变化。
- 同步 [Web 工程基线](./engineering/web-admin-baseline.md)、[总工程基线](./engineering/baseline.md)、[Web 设计映射](./design/web-management-ui.md)、[设计采用矩阵](./design/README.md)、`DESIGN.md`、README、必要的就近指令、CI、锁文件和发布说明。
- 完成正式 Web 构建与打包后的启动验证，并检查既有插件 iframe 的主题与通信兼容。

交付：单一 Web UI 栈、完整验证记录、迁移完成说明和可回退版本。

退出条件：无旧 Web 运行时入口和样式残留，必要 CI 与发布检查通过，计划状态转为完成。

## 交互与动效验收

以下参数是试点的起始配置，M0 评审后统一锁定，不能由每个页面自行调整。

| 场景 | 起始配置与可观察要求 |
| --- | --- |
| 弹窗进入 | 约 180–240ms；透明度与 `0.96 → 1` 轻微缩放；原点固定在自身中心，不从鼠标点击位置移入 |
| 弹窗退出 | 约 120–180ms；退出完成后释放节点、遮罩和焦点锁，焦点回到有效入口 |
| 异步内容 | 点击立即获得反馈；骨架和容器有稳定尺寸，加载后内容变化平滑，不能突然从小框跳成大框 |
| 连续操作 | 打开、关闭、重新打开及路由切换可取消或反向衔接；旧动画不能覆盖最新状态 |
| 控件反馈 | 约 100–160ms；禁用、忙碌、错误状态完整，提交不能因视觉延迟重复触发 |
| 日志与虚拟列表 | 不以逐条动画打断阅读；新增、筛选、分页、回到尾部和详情切换保持滚动锚点 |
| 降级 | `prefers-reduced-motion` 与 forced-colors 下保留即时反馈；无 View Transition 时所有功能可用 |

验收至少覆盖：

- 桌面 `1440×960`、窄屏 `390×844`、低高度视口、亮暗主题、键盘和减少动态效果模式。
- 弹窗进入动画中的实际帧；固定中心场景中心偏移不超过 1 CSS px。测试必须观察到动画中间状态，不能关闭动画后仅比较最终矩形。
- 不同位置的按钮、滚动后的页面、异步高度变化、嵌套确认、反复开关和浏览器前进后退。
- 必要操作完整可见，焦点不丢失或落到背景，关闭后无残留遮罩或滚动锁。
- 长文本、中英文混排、200% 缩放、触摸目标和表格局部滚动；普通页面无横向溢出。
- 使用正式登录流程建立测试会话；mock 后端同样走登录接口，不绕过 guard 或伪造本地鉴权状态。

性能采用同设备的基准对照：以 60Hz 下约 16.7ms 的帧间隔为初始观察目标，记录关键操作的帧间隔分布、超过 50ms 的长任务、资源体积与滚动稳定性。性能收益以试点测量为准，不承诺仅靠替换动画库达到固定帧率。

## 验证与共享分面

按[验证选择规则](../.agents/skills/repo-validation/SKILL.md)和[质量门禁](./engineering/quality-gates.md)运行与阶段相关的检查。

- 基础组件、公共交互和页面行为：最小有效单元测试与浏览器回归，重点断言用户可见结果。
- 类型和生产产物：在 `web/` 运行 `pnpm run typecheck`、必要测试和 `pnpm build`，确认生成页面与资源可使用；迁移完成时覆盖全 Web 验证。
- 动效：录制或逐帧采集真实过程，验证中间状态、取消与卸载；静态截图单独用于视觉和响应式检查。
- token：运行 `node scripts/generate-design-tokens.mjs --check`。共享 token 或生成脚本改变时检查 Web、Launcher 和字体/品牌生成物，按影响运行 Launcher 主题测试与相关验证。
- 插件：保持 [management UI 契约](../contracts/plugin-management-ui.yaml)和 [bridge schema](../contracts/plugin-management-ui-bridge.schema.json)；主题允许字段、握手、来源校验、失效会话、加载失败和 iframe 尺寸变化均需验证。没有契约变化时不制造生成类型 diff。
- 依赖与文档：更新实际锁文件和受影响的 third-party notices，运行 `node scripts/check-web-indentation.mjs`、`python scripts/check-doc-links.py`、`git diff --check`；修改指令时再运行 agent-doc 检查。

共享视觉源的变化可能改变 Launcher 外观，但不改变其 React/Fluent 框架。第三方插件的包内样式不由宿主强制覆盖；独立官方插件的组件迁移作为后续单独范围安排。

## 切换、提交与回退

- 每个可独立审阅的组件层或业务批次形成具体的 Conventional Commit。版本锁定、实现、测试和相应文档随同一个逻辑变化交付。
- 迁移过程中保留一套正式路由和业务状态；开发展示入口不得进入正式导航或长期保留两套同名页面。
- 正式路径按完整工作区切换，避免同一个表单混用两套控件和关闭机制。失败时可以撤销该批前端提交，不回写用户配置或数据库。
- `612c5bc3` 用于功能与视觉对照；实际回退以每批前一可用提交为起点，不能通过整仓重置覆盖无关或后续工作。
- 旧依赖在最后一个使用点清除后卸载；资源加载、偏好恢复、鉴权或插件 bridge 出现回归时，先修复或撤回该批，不继续扩大切换范围。

# 仓库清理执行计划

基线为 `64f16948`。清理允许破坏兼容，按可独立验证的领域分批实施。保留单进程模块化单体、SQLite 与现有工具链；每次只保留一条正式业务执行路径。编号对应 2026-09-09 仓库评审。

## 已落地的后端边界修复

| 事项 | 当前结果 |
| --- | --- |
| F01 命令刷新 | 注册、reload 和配置刷新共用命令投影；正则定向投递保持一致。 |
| F02 权限读取失败 | 黑名单、白名单及开关读取失败阻止事件执行，记录 `permission.unavailable`，不消耗冷却额度。 |
| F03 身份通知 | JSONL protocol v3 使用 `init.bots` 与 `bot.identities.changed` 完整快照，身份按适配器实例区分；SDK 按事件来源选择身份。 |
| F04、F17 启停接口 | 删除 handler 自行修改 catalog/repository 的备用路径；装配时要求生命周期控制器，测试验证委托、结果和错误映射。 |
| F06 动作注册 | 删除不参与运行的 schema/权限/审计元数据、可替换 registrar 框架及无调用者的 setter；契约集合检查改为读取实际注册动作。 |
| F07 部分依赖声明 | Governance 使用明确接口，插件路由在装配时校验依赖。其他服务构造器仍需继续整理。 |
| F08 部分依赖方向 | 提取 `internal/diagnostics`，CLI 和在线诊断共用；数据库配置路径解析归 `runtimepaths`。架构测试禁止领域导入 CLI/App。 |
| F18、F19 部分测试清理 | 有限 HTTP 错误场景采用明确状态/错误码断言；移除空目录、测试文件编号的阻塞测试。 |
| F24–F26 说明整合 | 更新多适配器和插件协议信息，纠正 catalog 验签说明，移除 README 中手写的完整 HTTP 路由镜像。 |

协议 v3 的破坏项、SDK 重建和备份边界见[升级说明](./release/plugin-protocol-v3-upgrade.md)。此次不删除用户配置、数据库、凭据或已安装插件目录。

## 后续批次

| 顺序 | 范围 | 验收重点 |
| --- | --- | --- |
| 1 | F05、F07、F08、F10：插件应用边界、runtime 中的跨领域模型、adapterRouter、其余命令匹配与前缀重复 | 领域不依赖进程 wire frame；有效命令只有一个来源；启动、配置刷新和 reload 行为一致。 |
| 2 | F09、F15：统一版本来源和账号领域；进一步收敛配置、身份与治理键的归属 | 未知版本不伪装成固定版本；账号状态与文案有唯一拥有者；不同 adapter/bot 的治理键不会混用。 |
| 3 | F11–F14、F16：Web 日志/表单重复、错误映射、旧文案和兼容导出 | 保留实时日志与历史查询差异，复用共同模型；错误资源与实际消费者一致。 |
| 4 | F20–F23：退休栈检查、Nightly 重复测试、E2E mock 边界、SQL 例外复审策略 | 每项阻塞检查有明确风险；核心跨层流程由真实 Server 验证；不因单纯日期变化阻止无关构建。 |
| 5 | F27：Launcher 进程、更新、监控与视图状态拆分，大型 Web 工作区整理 | 每个状态有单一拥有者；验证原生系统集成和页面生命周期，不按行数机械拆包。 |

`tasks` 与 `scheduler` 分别负责异步任务终态和定时触发；保留各自职责。认证、路径与归档校验、资源上限、并发保护、签名和恢复验证继续保留。

# 游戏插件返工计划

日期：2026-09-20。本计划依据同日对四个插件、共享库 `game-plugin-kit`、主仓库未提交改动和 `external/参考项目` 的只读审计制定，取代此前执行进度、交付验收与非受限台账三份文档中的完成声明；这三份过程台账已删除。插件路径均相对于主工作区同级的 `RayleaBotPlugins/`。

## 审计结论

保留的部分：

- 账号插件的密文存储（AES-256-GCM，整条记录加密）、代理请求（游戏插件不接触 CK）、宿主注入的调用方身份与默认关闭的允许名单、国服扫码登录流程。
- 主仓库的通用 `services`、`plugin.call`、`plugin.request`，不含加密或 CK 语义。
- 圣遗物、遗器、驱动盘评分公式，抽卡档案的 UIGF/SRGF 导入导出与增量合并。

需要返工的部分：

| 问题 | 证据 |
| --- | --- |
| 图片输出未复刻 | 上游 6 个插件约 165 个 HTML 模板；三个游戏插件各 1 个逐字节相同的“标题加键值表”模板，所有命令经 `game-plugin-kit/app.go:913` 使用它；接口返回的图标地址在 `views_extended.go:223` 被丢弃 |
| 触发词错误复刻 | 253 条命令全部是固定前缀的 `exact` 触发；内置别名原神 23 条、星铁 0 条、绝区零 37 条 |
| 命令未分组 | 每个游戏 1 个 72 至 82 条的大组加 1 个 8 条的小组；`help.go:75` 平铺并截断到 35 条 |
| 插件未独立成型 | 三个游戏插件由 `scripts/scaffold-development.py` 循环生成，各约 40 行 Go；逻辑集中在一个 115 文件、约 2.2 万行的扁平包，含 184 处游戏 ID 判断；`vault/` 位于游戏库，账号插件反向依赖它 |
| 批量脚本移植 | 276 个上游 `calc.js` 被改名为数字 ID 文件并由 goja 执行，每次计算新建虚拟机；评分规则另有 Python 转译路线，伤害另有自写 Go 路线 |
| 错误归于受限 | 素材许可、绝区零 10041、星铁抽卡 `-100`、minigg TLS、ark 验收、SDK tag，见[受限事项重判](#受限事项重判) |
| 功能缺漏 | 无 CK 的 `更新面板`、面板列表、练度统计、圣遗物列表、今日素材、国服 Cookie 与 SToken 导入、任意 UID 绑定、设备绑定、抽卡链接导入、绝区零技能图鉴 |

| 过度设计 | 密钥轮换、加密备份与跨机迁移、业务 ZIP 备份、别名冲突三策略、手填倍率伤害、39 个管理页组件、主仓库 `cancel` 帧与 0.7.1 门槛 |
| 卫生 | 5 个插件仓库与主仓库改动均未提交；共享库残留 408MB 构建副本；`external/参考项目` 7.5G，同批仓库 3 至 4 份 |

## 已确认决定

用户于 2026-09-20 确认：

1. **CK 密钥保护**：保留 DPAPI 自动解锁，沿用“已安装插件可信”的前提。同时修复两点：账号库只能由管理员在管理页初始化并选择模式，支持 DPAPI 与口令模式互相切换；非 Windows 平台只提供口令模式，聊天命令不得触发初始化。
2. **主仓库**：目前不保留 `cancel` 帧和 0.7.1 版本门槛。
3. **素材**：与上游一致，由管理员触发，从上游公开仓库下载到插件数据目录；攻略与地图在运行时拉取后发图；安装包不含第三方素材。
4. **命令前缀**：宿主新增插件专属命令前缀，按插件分别解析，专属前缀命中的候选遮蔽通用前缀命中的候选，设计见 [R0b](#r0b-宿主插件专属命令前缀)。保留不带符号的专属前缀（如 `星铁体力`）。原神插件只使用通用前缀。内置帮助菜单图片的前缀显示随之改进。

以下两项是本计划的默认做法，开工前可以否决：

- **伤害与评分沿用“执行上游脚本”路线，但只保留这一条**。上游每个版本都新增角色脚本，原生移植会成为长期维护负担；执行原脚本还能保证数值一致。改进点：文件名改为 `<ID>-<角色名>.js`，每个插件只嵌入本游戏脚本，虚拟机复用而不是每次新建并重跑 lodash；评分动态规则并入同一路线，删除 Python 转译器、`scoring_dynamic_generated.go` 和自写的 `damage/` 计算器。
- **ark-plugin 属于点名要求的范围，保留并补齐聊天入口**；只删除在它之上自创的分批导入导出、云归档和令牌保险库。

## 验收口径

- 用户可见功能以 Windows 实例上的 Core、真实账号和真实聊天消息验收，并与上游同一命令的输出对照。合成数据测试只用于回归，不能替代验收。
- 每个阶段结束时，相关仓库完成提交；提交遵守根 `AGENTS.md` 的 Git 规则，不推送。
- 受限项只登记经核对确实无法由本项目解决的外部条件。

### R0b 宿主插件专属命令前缀

用途与业务无关，任何插件都可以使用；宿主已有先例，内置菜单的 `builtin_features.menu.prefixes` 非空时即替代通用前缀。

1. 契约先行：`contracts/plugin-info.schema.json` 增加插件级声明，包含专属前缀列表与“是否响应通用前缀”；同步 fixtures、示例、`docs/plugin/manifest.md` 与 SDK 构建校验。旧 Core 因未知字段拒绝该清单，不设版本门槛。
2. 生效值归 Server：清单提供默认值，管理员可在管理页按插件覆盖。前缀是匹配条件，不是所有权：专属前缀可以与通用前缀或其他插件的专属前缀相同，任何声明组合都有确定的投递结果，不存在需要先解决才能运行的冲突状态。
3. 按插件解析：每个插件的生效前缀是自己的专属前缀，加上通用前缀（未关闭时）。宿主用该插件的生效前缀按最长优先解析消息，得到命令名与参数，再与该插件的触发器匹配；命中即成为候选。专属前缀可以单独出现，也可以跟在通用前缀之后（`*体力`、`星铁体力`、`/星铁体力` 都解析为星铁插件的 `体力`）。事件里的 `command` 与 `args` 按各候选自己的解析结果填写。
4. 候选排序：经专属前缀命中的候选优先于经通用前缀命中的候选，存在前者时不再投递后者，内置帮助菜单归入后者；同一层内沿用现有的 `priority` 分层、`block` 与 `propagation` 规则。权限取留存候选中最严格的一级，冷却与黑白名单沿用现有规则。
5. `init.command_prefixes` 改为下发对该插件生效的前缀。管理面在同层、同优先级的多个插件会同时响应同一写法时提示重叠，不阻止运行。
6. 内置帮助菜单图片（`templates/help.menu/`）的前缀显示。现状是页头列出一份全局前缀，每条命令的用法前面只有一个“前缀”占位字样；插件有了专属前缀后，这种显示会给出错误的写法。改为：
   - 单个插件的帮助页，页头列出该插件的生效前缀，专属前缀排在前面并与通用前缀在视觉上区分；关闭通用前缀的插件不显示通用前缀。
   - 每条命令的用法用该插件的首选前缀写成可直接发送的完整示例（如 `*体力`、`/雷神面板`），不再使用“前缀”占位字样；首选前缀取第一个专属前缀，没有专属前缀时取第一个通用前缀。
   - 多插件总览页，每个插件的卡片显示自己的前缀。
   - 同步 `input.schema.json`、`preview.json` 与 `server/internal/bot/menu/` 的数据组装；视觉细节按 `docs/design/README.md` 的流程处理并由人工审核。
7. 测试：按插件的最长前缀解析、专属层对通用层的遮蔽、同层按优先级分层与未处理下沉、关闭通用前缀后的隔离、每个候选收到自己的 `command` 与 `args`、配置热更新后的匹配器替换、帮助菜单数据中各插件的前缀与示例。

### R3 命令层

宿主的命令前缀是全局配置 `command.prefixes`（当前实例为 `/`、`*`、`~`），对所有插件等价；前缀后的第一个词交给触发器匹配，事件只携带 `command` 与 `args`，不携带命中的前缀。带游戏名的写法（`/星铁希儿面板`）现有宿主即可支持；按前缀区分游戏（`*体力` 归星铁、`%体力` 归绝区零）依赖 [R0b](#r0b-宿主插件专属命令前缀) 的宿主能力。

1. 命令改用 `pattern` 触发，保留上游写法：`体力`、`雷神面板`、`更新面板`、`深渊`、`上期深渊`、`今日素材`，以及上游命令的同义词。
2. 游戏归属：星铁与绝区零插件声明专属前缀并关闭通用前缀，命令名不带游戏名；原神插件只使用通用前缀。三个插件的同名命令（如 `体力`）由前缀区分，互不唤醒。专属前缀的默认值取自上游，管理员可在管理页修改：
   - 星铁：`*`、`＊`、`星铁`、`星轨`、`崩铁`、`星穹铁道`、`铁道`、`sr`。
   - 绝区零：`%`、`％`、`绝区零`、`绝区`、`zzz`、`ZZZ`。
3. 导入上游别名表：miao 的 `meta-gs` 与 `meta-sr` `alias.js`、ZZZ-Plugin 的 `defSet/alias.yaml`。
4. 角色名解析优先采用精确命中，修复星铁 17 个角色的未唯一匹配。
5. `command_groups` 按功能分组，参考上游帮助的分组：信息查询、角色面板、战绩、抽卡、养成与资料、签到与提醒、排名、管理。`帮助` 按组输出，取消 35 条截断。
6. 删除 `app.go:117` 的 4 秒超时，使用宿主事件超时；公告、攻略、日历改为一步返回结果；抽卡同步在单次事件内连续翻页，页间隔沿用上游的 300 至 500 毫秒。
7. 面板命令默认同时给出属性、评分和伤害，不再要求手输规则编号。

### R4 图片输出

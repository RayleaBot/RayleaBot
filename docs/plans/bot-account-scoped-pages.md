# 插件管理页按机器人账号分页

状态：设计待确认，尚未实施。

## 背景

插件的主动推送与黑白名单已改为按“协议 + 机器人账号 + 目标”寻址（主仓库 `7d7200ce`、`783ded45`）。宿主在发送时选择当前登录该账号的连接，删除重建连接或修改连接标识后，插件保存的地址仍然有效。

管理界面没有跟上这个模型：

- 协议中心按连接管理，机器人账号只是连接卡片上的一项资料，界面上没有独立的账号对象。
- 插件管理页把所有账号的数据混在一个列表里。连接 A 登录账号 A、订阅了 1，连接 B 登录账号 B、订阅了 2，订阅中心会把两者列在一起。每一行各自带一个机器人选择框，使用者既看不出某条数据属于哪个连接，也容易误以为会推送到所有连接，或者以为换了连接后仍然经旧连接发送。
- 各插件各自拼凑账号列表：订阅中心与轮盘读 `/api/adapters`，米游社账号与游戏插件读后端事件中的 `Bots`。显示格式各不相同，账号离线或连接被删后只能显示一个裸号码。

## 目标

- 一个账号一页：账号与连接一一对应，按账号分页即对应使用者理解的“一个实例一页”，数据归属账号，换连接后跟随账号。
- 账号切换由宿主统一提供，各插件不再各做一套账号标签和机器人选择框。
- 账号离线或连接被删后，账号与其数据仍可见，并写明当前状态和恢复方式。
- 只有全局设置的插件与页面保持现状。

## 设计

### 账号目录

服务端持久化见过的机器人账号，作为“机器人账号”这一对象的唯一来源。插件与 Web 不再从连接列表或事件身份自行推断。

| 字段 | 说明 |
|---|---|
| `source_protocol`、`bot_id` | 账号标识，与投递地址、黑白名单作用域一致 |
| `nickname`、`avatar_url` | 最近一次确认的资料，可缺省 |
| `adapter_id` | 账号当前所在的连接；连接下线或被删除后保留最后所在的连接 |
| `state` | `online`：所在连接已连接；`offline`：连接存在但未连接；`no_connection`：所在连接已删除，或已改登其他账号 |
| `last_seen_at` | 最近一次确认在线的时间 |

- 连接确认身份时写入或更新该账号的记录。同一账号不会同时登录两条连接，目录按一个账号一条所在连接建模。
- 一条连接改登其他账号后，原账号转为 `no_connection`，它的数据仍挂在原账号下。
- 管理 API 提供账号列表，变化时通过 `/ws/events` 的 `events.received` 发出 `bot_accounts.changed`，页面实时更新。
- 只有 `no_connection` 状态的账号可以由管理员从目录中移除；移除只影响目录，不删除插件数据。

### 页面范围声明

manifest 的 `management_ui.pages[]` 新增可选的 `scope`：

- `global`：缺省值，行为与现在相同。
- `bot_account`：该页面的数据按账号划分，由宿主提供账号切换。

声明以页面为单位，同一个插件可以同时有全局设置页和按账号的数据页。

### 宿主外壳

声明为 `bot_account` 的页面，宿主在 iframe 上方显示账号切换栏：

```
订阅中心 · 订阅设置
[ napcat-home · 小雷（123456） ]  [ qq-official · 小月（654321） ]  [ 小星（778899）· 无连接 ]
────────────────────────────────────────────
（插件页面：只显示小雷的数据）
```

- 标签为“连接名 · 账号”，连接名在前，与按实例的理解方式一致。离线与无连接的账号排在后面并标明状态。
- 只有一个账号时不显示切换栏，只在页面顶部写明当前账号。没有任何账号时，页面说明需要先在协议中心添加连接。
- 当前账号写入插件详情页地址（查询参数 `bot=<协议>:<账号>`），可以收藏和分享。切换账号即用新参数重新加载 iframe。
- 协议中心的每张连接卡片列出该连接所在账号的 `bot_account` 页面，点击后打开对应页面并选好该账号。

### 页面与插件之间的传递

不恢复已删除的管理页消息桥，沿用现有的地址参数与管理 API：

- 宿主把当前账号放在 iframe 地址的查询参数中，与已有的 `page` 参数并列。Vue SDK 的 `PluginUIClient` 解析后通过组合式函数提供给页面，包括账号资料与所在连接，供页面显示。
- `invokeAction` 在 `bot_account` 页面中自动在请求体里附带 `bot: {source_protocol, bot_id}`。`PluginManagementActionRequest` 新增该可选字段。宿主核对账号存在于目录后，写入 `management.action` 事件的 `payload.bot` 转给插件；账号不存在时按现有请求校验错误拒绝，不投递。
- Go SDK 提供从管理事件读取账号的方法，插件后端据此过滤与写入。
- 插件设置（`/api/plugins/{id}/settings`）保持全局，按账号划分的数据由插件通过管理动作读写自己的存储。

### 插件侧约定

- `bot_account` 页面只显示当前账号的数据；新建的条目归属当前账号，不再逐行选择机器人。
- 旧数据中补不齐账号的记录，在每个账号页顶部提示“有 N 条记录未分配发送账号”，并提供“归入当前账号”。
- 与账号无关的设置放在 `global` 页面，或页面中明确标为全局的区域。
- 各插件哪些页面声明为 `bot_account`、旧数据如何归属，在各插件仓库的 `docs/` 中说明。主仓库只提供宿主能力与 SDK。

### 契约改动

| 契约 | 改动 |
|---|---|
| `contracts/plugin-info.schema.json` | `management_ui.pages[].scope`，枚举 `global`、`bot_account`，缺省为 `global` |
| `contracts/web-api.openapi.yaml` | 账号目录的列表与移除接口；`PluginManagementActionRequest.bot` |
| `contracts/websocket-events.yaml` | `events.received` 的 `bot_accounts.changed` |
| `contracts/plugin-protocol.schema.json` | `management.action` 事件的 `payload.bot` |
| `contracts/plugin-management-ui.yaml` | iframe 地址携带当前账号的查询参数 |

manifest 与插件动作数据都按严格解码处理，旧宿主会拒绝带新字段的插件包。这些字段应在 v0.4.0 正式版之前进入契约：manifest v4 插件只能安装到 0.4.0 正式版及之后的宿主，届时不需要额外的版本门槛。

## 实施步骤

1. 契约与样例：上表各项，以及对应的 fixtures 与 HTTP 示例。
2. 服务端：账号目录的持久化（数据库前向迁移）、维护、管理 API 与实时事件；管理动作的账号核对与转发。
3. Web：插件详情页的账号切换栏与地址参数，协议中心连接卡片的插件页面入口，删除连接确认中的账号说明改为读取账号目录。
4. SDK：Vue SDK 解析当前账号、`invokeAction` 附带账号；Go SDK 读取管理事件中的账号。
5. 插件：订阅中心（订阅设置、链接解析的推送对象）、轮盘（群设置）、原神、星铁、绝区零（群设置、提醒、内容推送）、米游社账号（账号列表）依次声明页面范围并按账号过滤。各插件的细节写在其仓库内。

## 验收

- 两条连接分别登录账号 A 与 B：订阅中心的订阅设置页按 A、B 分页，各自只显示自己的订阅；地址带 `bot` 参数时直接打开对应账号页。
- 删除 A 的连接：A 的页签仍在并标为无连接，数据完整；新建连接并登录 A 后，页签显示新连接名，推送恢复。
- 连接改登账号 C：C 出现为新页签，A 转为无连接，A 的数据不出现在 C 的页面中。
- 未声明 `scope` 的插件与页面行为不变。
- 管理动作携带目录中不存在的账号时被拒绝，不投递给插件。

## 暂不包含

- 机器人换号迁移：使用者在账号目录中执行“账号 A 已更换为 B”，宿主通知插件改写保存的地址。只适用于 OneBot11，待本计划落地后再评估。
- 按目标记录最近一次实际投递（时间、经由连接、成功与否）：属于各插件的显示改进，在插件计划中安排。

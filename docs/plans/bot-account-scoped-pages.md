# 插件管理页按机器人账号分页

状态：设计待确认，尚未实施。下述为推荐实施方案，正式行为仍以现行契约为准。

## 背景

插件的主动推送与黑白名单已改为按“协议 + 机器人账号 + 目标”寻址（主仓库 `7d7200ce`、`783ded45`）。宿主在发送时选择当前登录该账号的连接，删除重建连接或修改连接标识后，插件保存的地址仍然有效。

管理界面没有跟上这个模型：

- 协议中心按连接管理，机器人账号只是连接卡片上的一项资料，界面上没有持久化的账号对象。
- 订阅中心等页面把多个账号的数据放在同一列表，条目各自保存发送账号；轮盘也在插件页面内选择机器人和群覆盖。连接 A 登录账号 A、订阅了 1，连接 B 登录账号 B、订阅了 2，使用者不容易看清各自的数据归属。
- 订阅中心与轮盘从 `/api/adapters` 取得账号；米游社账号与游戏插件通过管理动作结果取得后端的 `event.Bots`。这些来源都不是历史账号目录，账号资料和离线表现也不统一。

现行边界：

- [manifest](../../contracts/plugin-info.schema.json) 的 `management_ui` 是单入口 `entry` 加 `pages[]`，页面只有 `id`、`label`，没有 `scope`；[Web API](../../contracts/web-api.openapi.yaml) 的 `PluginManagementUIPage` 另有同形投影，也需要同步。
- [管理页契约](../../contracts/plugin-management-ui.yaml) 只规定同源静态资源、缓存与 CSP。页面直接使用管理员会话调用 API，没有消息桥。[Vue SDK](../../sdk/vue/src/client.ts) 当前只从地址读 `page`，再请求插件详情、全局设置和密钥配置状态；地址参数本身不包含账号资料。
- 管理动作 HTTP 请求只有 `action` 和可选 `payload`。外层严格解码，业务 `payload` 是开放对象。服务端在 [HTTP handler](../../server/internal/management/plugin_ui_http.go) 接收请求，由 [lifecycle controller](../../server/internal/plugins/lifecycle/controller.go) 生成 `management.action`，来源固定为 `management` / `management.ui`，业务输入位于 `event.payload.payload`。
- [机器人身份聚合](../../server/internal/app/bot_identity.go) 提供启用实例的已确认身份；`init.bots` / `bot.identities.changed` 按实例替换快照，不持久化历史账号。OneBot 的该聚合使用在线的 `CurrentBotID()`，与管理面可从 `get_login_info` 取得资料的路径并不相同。
- 维护者确认一个账号同一时间只登录一条连接，本设计按此前提提供“一个实例一页”。现行[插件协议](../../contracts/plugin-protocol.schema.json)仍允许同账号的多个实例身份，并规定主动投递取配置顺序中的首个在线匹配实例；本计划不改此路由语义，也不把一一对应误写成现有校验保证。

官方插件根目录的 `info.json` 中，订阅中心声明 `accounts`、`subscriptions`、`resolver`、`resolver-strategy`；轮盘只有 `settings`，米游社账号只有 `accounts`；原神、星铁、绝区零各有多个页面，星铁使用 `tasks`、`groups` 等 ID；运势只有全局设置页。其余已查阅插件未声明管理页。不能把“群设置”“提醒”等业务名称直接当作各插件已有的页面 ID，也不能将订阅中心的平台账号管理与机器人账号混为一谈。

## 目标

- 一个账号一页：按账号分页对应使用者理解的“一个实例一页”，数据归属账号，换连接后跟随账号。
- 账号切换由宿主统一提供，各插件不再各做一套账号标签和机器人选择框。
- 账号离线或连接被删后，账号与其数据仍可见，并写明当前状态和恢复方式。
- 只有全局设置的插件与页面保持现状。

## 设计

### 账号目录

服务端持久化已确认的机器人账号，作为管理页账号目录的唯一来源。目录记录账号与连接的关系；发送仍由现有路由按实时身份选择连接，不把目录缓存当成在线依据。

| 字段 | 说明 |
|---|---|
| `source_protocol`、`bot_id` | 联合唯一键；协议为 `onebot11` 或 `qqofficial`，账号是非空字符串，与投递地址、黑白名单作用域一致 |
| `nickname`、`avatar_url` | 最近一次确认的资料，可缺省；头像沿用管理 API 的 HTTPS 限制 |
| `adapter_id`、`adapter_display_name` | 当前仍关联的连接及展示名；无连接时省略，不能用最后所在连接冒充当前连接 |
| `last_adapter_id`、`last_adapter_display_name` | 最后确认归属的连接，供无连接时说明历史来源，不参与寻址 |
| `state` | `online`：当前运行实例已确认此账号且连接在线；`offline`：关联连接仍存在但未在线确认，包含停用、重连与身份待确认；`no_connection`：关联已解除 |
| `last_seen_at` | 最近一次在有效运行实例中确认在线的 UTC 时间；重复在线确认最多每分钟持久化一次，不等同于最近消息时间 |

身份与生命周期：

- OneBot 使用有效实例收到的 `self_id` 或成功的 `get_login_info.user_id` 确认账号，昵称只接受与该账号相符的登录资料；覆盖 HTTP API 无聊天事件和 Webhook 收到事件的路径。QQ 官方使用 `READY.user.id`，昵称来自 READY 或匹配同一 ID 的 `/users/@me` 资料；不使用 AppID、连接 ID 或昵称代替账号，不将 QQ 官方 ID 当作 QQ 号或数字转换。
- 目录维护接入身份确认、资料更新、连接状态和配置变更的服务端路径，不能等打开管理页或收到业务消息才写入。身份提供者的快照读取保持只读；现有 `Bots` 保留原语义，不混入离线历史账号。
- 新身份确认时，按联合键 upsert；同一事务解除该连接原账号的关联并绑定新账号。账号换到新连接时更新关联，插件数据不变。连接删除或改登其他账号后，旧账号转为 `no_connection`；停用或短暂断线只转为 `offline`。可能改变登录身份的配置替换先撤销旧绑定，待新运行实例重新确认；仅改展示名不撤销。
- 写入与移除由同一服务串行化，数据库唯一约束防止重复账号和重复绑定；内存读取使用锁或不可变快照。回调关联运行实例代次，忽略被删除、替换实例的迟到身份与下线通知；A 的旧连接下线不能覆盖 A 已建立的新绑定。若快照意外出现重复在线账号，按现有投递顺序选择关联并记录诊断，不按回调到达顺序反复切换。
- 只有事务提交成功后才更新目录快照并通知 Web；失败保留最后成功结果、记录错误并重试，不能发布未落库的账号。状态和资料变化及时持久化；重复心跳不逐帧写库或推送。
- 启动或恢复时先装载目录并核对现有配置：连接已不存在的账号为 `no_connection`，其余为 `offline`，重新确认后才在线。升级首次建表为空，不从日志、AppID 或插件私有存储猜测历史身份；升级前已离线且未被新宿主确认的账号数据走下述历史数据入口。

管理 API 推荐如下，均使用现有管理会话；写操作沿用 CSRF 校验：

| 接口 | 行为 |
|---|---|
| `GET /api/bot-accounts` | 复用现有集合分页：`limit` 默认及最大 100，`cursor` 为十进制偏移、缺省 0；可按 `source_protocol`、`state` 和 `query`（账号、昵称、当前或最后连接名）筛选；返回 `items`、`total` 和有后续页时的 `next_cursor`，空列表为 `items: []`、`total: 0`，省略 `next_cursor` |
| `GET /api/bot-accounts/{source_protocol}/{bot_id}` | 读取指定账号，供深链和 SDK 使用；不依赖其是否在已加载的列表页内 |
| `DELETE /api/bot-accounts/{source_protocol}/{bot_id}` | 仅允许移除 `no_connection` 账号，成功返回 204；与重新登录串行核对，已有连接则返回 409 / `platform.state_conflict` |

历史账号会持续累计，目录不设总数上限、不按时间自动淘汰，使用现有分页约定控制单次响应。列表固定按 `online`、`offline`、`no_connection` 分组，再按 `source_protocol`、`bot_id` 的字符串升序排列，避免昵称或最近活跃时间变化导致无关重排。筛选先于分页，集合或查询变化后从 cursor 0 刷新已加载页数，不承诺跨页不可变快照。参数非法返回 400 / `platform.invalid_request`，单项不存在返回 404 / `platform.resource_not_found`；管理动作引用不存在账号仍按请求校验错误返回 400。

目录变化通过 `/ws/events` 的 `events.received` 发送 `{event_type: "bot_accounts.changed", summary: "机器人账号目录已更新"}`，复用 OpenAPI 中的 `ManagementEvent` 分支，不新增 WS 频道或原始聊天事件。Web 按 `event_type` 回拉已加载列表和当前账号，不解析 `summary`；合并密集通知。首次进入、WS 重连、页面恢复激活时回拉，活动页面每 60 秒兜底刷新，不能依赖此频道重放补齐变化。

移除只删除目录记录，不删除插件数据、不改变黑白名单或投递地址。移除确认必须说明账号页将不可访问；插件的全局历史数据入口仍能查看和清理这些记录，重新登录同一协议和账号后重新入目录、恢复原数据归属。移除前检查目录状态，不能声称宿主知道所有插件的关联记录数。目录移除与插件数据清理不做跨插件级联事务。

### 页面范围声明

manifest 的 `management_ui.pages[]` 新增可选的 `scope`：

- `global`：缺省值，行为与现在相同。
- `bot_account`：该页面的数据按账号划分，由宿主提供账号切换。

声明以页面为单位，同一个插件可以同时有全局设置页和按账号的数据页。同步 manifest 解码模型、目录快照、管理详情投影与 OpenAPI 的 `PluginManagementUIPage`，缺省值统一解释为 `global`。范围不声明插件支持哪些聊天协议；只支持 OneBot 的页面选到 QQ 官方账号时明确提示不支持，并由插件后端拒绝相关操作，不把 QQ 官方 ID 送进 OneBot API。

### 宿主外壳

声明为 `bot_account` 的页面，宿主在 iframe 上方显示账号切换栏：

```
订阅中心 · 订阅设置
[ napcat-home · 小雷（123456） ]  [ qq-official · 小月（bot-id） ]  [ 小星（778899）· 无连接 ]
────────────────────────────────────────────
（插件页面：只显示小雷的数据）
```

- 标签为“连接名 · 昵称（账号）”，同时可辨协议；无昵称时显示账号，无连接时使用账号与状态，最后连接名只作历史说明。QQ 官方标为“机器人 ID”，不用 QQ 号头像规则。
- 只有一个账号时只显示当前账号摘要；多账号时最多展示 6 个快捷项，当前账号始终可见，其余通过可搜索、分页加载的“全部账号”选择器访问。无连接账号不按时间自动折叠或隐藏，按统一排序排在后面；这样既保留历史入口，也不把所有账号挤进切换栏。展示上限不限制可选账号总数。
- 目录为空时不加载账号 iframe：没有配置连接则引导添加连接，已有连接但身份未知则提示等待登录确认，并提供协议中心入口。目录全为 `offline` 或 `no_connection` 时仍能选择账号、读取和编辑已保存数据；需要在线连接的群列表、身份查询或即时发送单独提示不可用，不能将空结果保存为清空数据。
- 账号列表加载失败与真正空目录分别呈现。显式 `bot` 非法、不存在或被移除时保留地址、停止账号 iframe 并提示重新选择；不能静默切到其他账号后继续编辑。未指定账号时选择排序中的首项并补齐地址，之后状态重排不改变当前账号。
- 详情页使用现有 `/plugins/:id?panel=management-ui&management_page=<页面ID>&bot=<协议>:<账号>`，iframe 使用 `page=<页面ID>&bot=<协议>:<账号>` 并保留现有 `version`、`frame` 参数。通过 URL API 编解码，只在第一个冒号处分隔协议与账号；拒绝重复、空值和未知协议，账号部分按字符串原样使用。
- 在 `management-links.ts` 与 `usePluginDetailPanels.ts` 中统一生成和规范化参数。切换账号保留 `panel`、`management_page`；切换到另一个账号页保留账号，切换到总览或 `global` 页移除 `bot`，不把总览内部 `summary` / `commands` / `console` 的本地页签状态混入这组参数。自动补齐用 replace，主动账号切换用 push，使前进、后退恢复所选账号。
- 查询参数变化沿用现有详情页实例。iframe 的重载键必须包含插件、版本、来源、页面、scope 和账号联合键，账号切换销毁旧 iframe；仅昵称、连接名或在线状态变化不重载 iframe。保留现有未验证来源确认与插件启动完成后的重载行为，不用整个 `route.fullPath` 重建宿主页面。
- 插件页面的缓存、草稿、群列表和请求结果按插件、页面、协议、账号隔离；切换后不复用旧账号结果。持久草稿须带同样的键，SDK 文档明确切换会重载页面。旧请求即使在切换后完成，也只能作用于发出时的账号；卸载或取消请求不代表服务端已撤销写入。
- 协议中心连接卡片从目录取得当前关联账号，列出已安装插件的 `bot_account` 页面入口；未确认身份时不拼造账号深链。删除连接提示从目录取账号资料，删除后保留账号页；协议中心另提供无连接账号的目录移除入口。

### 页面与插件之间的传递

沿用同源地址参数和管理 API，不恢复消息桥。

Vue SDK 在 `loadContext` 中读取详情里的页面声明，解析账号键，再通过目录单项接口取得账号资料和当前连接，供 `usePluginHost` 暴露。URL 只承载标识，不传昵称、连接状态或资料 JSON。SDK 提供显式刷新当前账号资料的方法，首次加载和执行在线查询前使用；宿主外壳通过目录刷新展示实时状态，SDK 的初始化快照不作为投递依据。

管理动作增加可选 `page_id` 与 `bot: {source_protocol, bot_id}`。SDK 对声明为 `bot_account` 的页面必须携带两者，账号无效时停止动作；`global` 页面可带 `page_id`，不带 `bot`。旧页面与直接客户端省略两者仍走现有行为。

宿主在 HTTP 边界核对：

- 会话与 CSRF 有效，插件和管理页有效；外层请求及 `bot` 对象形状严格解码。
- 提供 `page_id` 时必须是该插件已声明的页面；`bot_account` 页面要求 `bot`，`global` 页面拒绝 `bot`；提供 `bot` 却缺少 `page_id` 也拒绝。
- `bot` 的协议和账号完整、存在于目录；离线和无连接不构成拒绝理由。非法输入统一返回 400 / `platform.invalid_request`，不投递；插件未运行仍为 409 / `plugin.not_running`，已尝试动作失败仍为 502 / `plugin.management_action_failed`。

宿主不能证明请求真的来自地址所写的页面：同源管理页和已登录客户端可以自行构造请求，页面声明与账号选择不是管理员权限隔离。插件动作名未绑定 manifest 页面，客户端也能省略 `page_id`；因此插件必须按动作自己的语义要求账号，不能因“旧格式兼容”而放行无账号的账号级写入。

宿主生成的事件保持原来源，载荷如下；`bot` 和 `page_id` 是宿主写入的同级字段，不能从业务输入提升或合并：

```json
{
  "event_type": "management.action",
  "source_protocol": "management",
  "source_adapter": "management.ui",
  "payload": {
    "action": "records.list",
    "page_id": "records",
    "bot": { "source_protocol": "onebot11", "bot_id": "123456" },
    "payload": {}
  }
}
```

Go SDK 提供读取管理事件账号的类型与方法，校验事件类型、管理来源和账号形状；它不从嵌套业务 `payload` 或 `event.Bots` 猜测当前账号。插件后端只需此上下文和自身存储，不新增账号目录 local action，也不把历史目录塞进 `init.bots`。HTTP 接纳后移除目录不撤销已在执行的动作；后续请求重新校验目录。

插件须按完整账号键过滤读取、新建、修改、删除、批量和后台任务。按记录 ID 修改或删除时仍要核对已有记录归属；业务参数中的 owner、subject、bot_id 与当前账号冲突时拒绝，不能仅信任前端过滤。聊天事件与调度仍使用各自的正式来源和持久化地址。

`management.action` 中发起的 `plugin.call` 也要保留账号。现有 `service_origin` 只有事件来源、可选 `bot_id` 等字段，运行时只复制事件顶层身份，管理动作的账号会丢失。推荐新增可选 `service_origin.bot`，仅从宿主接纳的管理事件 `payload.bot` 复制；`source_protocol` / `source_adapter` 仍为 `management` / `management.ui`，不伪装成聊天来源，也不把账号协议写进事件顶层。全局管理动作不带 `bot`，聊天来源继续使用现有字段，`event.detach` 后保留原账号。

米游社账号服务目前把管理来源视为管理员调用，允许显式 subject 或全量列表。接入账号页时，服务提供者必须以 `origin.bot` 限制账号级列表和资源访问，并核对 subject / 记录归属；调用方不能通过 `params` 提供或覆盖 origin。无 `origin.bot` 的调用只保留明确定义的全局管理操作，不能作为账号动作的绕过方式。此项需服务提供者与调用方在各自仓库同步后才能验收。

### 插件侧约定

- `bot_account` 页面只显示当前账号的数据；新建条目归属当前账号，不再逐行选择机器人。
- `/api/plugins/{id}/settings` 保持全局，不提供账号隔离。现有订阅中心通过 `saveSettings` 写设置，轮盘的 `settings.save` 也接受整份配置；不能只在 UI 过滤后回写这个子集。账号页改用管理动作，由插件后端在锁或事务内读取最新数据、只合并当前账号的改动并持久化，保留其他账号和全局设置。各写入口及旧数据迁移共享并发保护，不能仅锁住一次底层写入。
- 与账号无关的设置放在 `global` 页面，现有混合页相应拆分；宿主不替插件判定某个业务字段的范围。
- 已有完整账号键但目录中不存在的记录，与缺少账号的旧记录分开处理。插件提供全局“历史数据与归属”入口，按已保存的协议和账号列出记录并支持查看、清理；页面用目录单项查询确认是否存在，不能以“不在已加载第一页”判为目录外。后端返回自身记录的账号键即可，不需要持有目录副本；全部账号被移除或从未确认过时，该全局入口仍可打开。
- 缺少账号或归属有歧义的旧记录集中在该入口处理，不在每个账号页重复显示同一批“未分配”记录。仅当协议和目标身份可以确认仍然有效时允许显式归属；QQ 官方 openid 属于原机器人命名空间，不能把记录改挂到另一账号来恢复。已有完整账号键的目录外记录也不能当作未分配记录重新认领。
- 管理面读取目录中的 `adapter_id` 只用于即时目标查询，发送地址继续保存协议与账号。现有 OneBot 目标接口按连接寻址；查询前刷新账号关联，查询后重新核对关联和账号，变化则丢弃结果重试，不把旧连接返回的目标写给新账号。插件后端需要在线 API 时优先使用已有按账号寻址的宿主动作。
- 各插件页面拆分、全局动作清单、旧数据归属和服务方法约束在各插件仓库的 `docs/` 中维护。主仓库提供契约、宿主能力和 SDK，不在本计划展开独立插件的业务实施清单。

| `contracts/web-api.openapi.yaml` | 账号目录列表、单项与移除接口，分页、状态、错误；`PluginManagementUIPage.scope`；`PluginManagementActionRequest.page_id`、`bot` 及组合约束；`ManagementEvent` 中的目录变更语义 |

| `contracts/backup-manifest.schema.json` | 纳入新增数据库版本，保持旧版本可前向迁移；无需增加独立账号目录文件或清单字段 |

新增表接在当前 `000009` 迁移之后；若实施时无其他迁移占号，使用 `000010`。同步 `schema.sql`、迁移链和 sqlc 查询生成物，不修改历史迁移。目录随现有完整 SQLite 快照备份和恢复；旧备份前向迁移为空目录，随后由身份确认补齐，新备份保留账号资料和关联，恢复后重新判定在线状态。按影响同步备份 fixtures、恢复说明与恢复演练数据。

兼容性按方向区分：manifest 新字段会被旧宿主拒绝，管理 HTTP 请求的外层新字段也会被旧宿主拒绝；业务 `payload` 并非宿主严格定义的插件业务 schema。宿主到插件的新可选字段沿用[合同兼容承诺](../plugin/README.md#合同兼容承诺)，接收方忽略未知字段，不能倒过来要求旧 SDK 理解新账号语义。

推荐在 v0.4.0 正式版定版前完成，此时使用该能力的插件仍可声明 `min_core_version: 0.4.0`。这取决于该正式版确实包含完整能力，不能仅凭 manifest v4 推导所有 0.4.x 宿主都支持；若晚于该版本交付，插件须将最低版本提升到首次支持此能力的核心版本。先发布宿主和 SDK，再发布使用新 scope 的插件包，保留旧页面缺省全局及旧动作格式的兼容用例。

## 实施步骤

1. 契约与样例：先固定上述字段、分页、状态、参数组合、来源与错误语义。补齐 manifest scope 缺省/合法/非法值、管理动作有效账号/缺失/冲突、管理服务 origin、目录列表/空列表/移除竞争、WS 通知和新旧备份的 fixtures；新增或改名 fixture 登记到对应 `x-fixtures`，HTTP 示例登记到 `examples/http/index.yaml`。
2. 生成与存储：同步运行时 manifest / backup schema 副本、Server 与 Go SDK 的 plugin wire 模型、协议 schema 与样例帧、Web 的 OpenAPI / WS 类型；新增数据库迁移和目录查询后更新 sqlc 产物。使用现有生成脚本，不手改生成物或另建接口模型。
3. 服务端：实现目录维护、启动恢复、串行化与过期回调保护、管理 API 和通知；打通 manifest scope 到插件详情的投影；在管理动作 HTTP 接纳和 lifecycle 投递间传入独立账号上下文，扩展服务调用 origin，保留既有来源与错误映射。
4. SDK 与宿主示例：Vue SDK 解析和校验页面上下文、查询账号资料、自动附带 `page_id` / `bot`；Go SDK 读取管理事件和服务 origin 的账号。示例同时提供全局页和账号页，验证直连 API 与跨插件服务传递。
5. Web：统一详情页深链与参数规范化，账号切换、空状态、iframe 重载和缓存隔离；协议中心添加账号页入口和目录移除操作，连接删除说明读取目录。依赖目录 API 和 scope 投影就绪。
6. 插件接入：宿主与 SDK 可用后，由相关插件仓库确定页面拆分并改造账号级读写、历史数据入口。米游社账号服务与游戏调用方先完成 origin 约束，再验收它们的账号页；订阅中心和轮盘重点验证整份设置写入改造。保留运势等全局页作为兼容样例。
7. 文档与交付：同步契约索引、插件 manifest / 管理页 / 协议 / SDK 文档，以及用户管理面、恢复和发布说明；只更新受影响的现行说明。主仓库按[质量门禁](../engineering/quality-gates.md)完成契约严格校验、受影响生成器漂移、存储/并发/管理动作与 SDK/Web 验证，确认生成产物；插件在各自仓库验证。能力落地并写入现行文档后删除本计划。

## 验收

业务、边界与并发行为在最小可靠层次验证，视觉布局和标签表现人工审核。

- **身份来源与持久化**：OneBot 在仅有 `get_login_info`、仅有有效入站身份的路径均能入目录；QQ 官方目录 ID 等于 `READY.user.id`，AppID 不入目录；资料缺失不生成假账号。重启后离线账号仍在，未确认身份不显示在线。
- **生命周期与并发**：A、B 各一条连接时目录各一项；删除 A 的连接后 A 为无连接，原数据完整；新连接登录 A 后关联更新，投递使用新连接。原连接改登 C 后 A 为无连接、C 为新账号，A 的数据不出现在 C 页。迟到回调、重复通知、并发移除和重新登录不恢复旧绑定、不重复建行；写库失败不发布成功目录。
- **深链与隔离**：带 `panel`、`management_page`、`bot` 的地址直接打开目标账号及页面；多于 100 个账号时仍能通过单项深链找到未加载的账号。切页保留或移除 `bot` 符合范围规则，前进后退恢复账号；切换 A 到 B 后不出现 A 的列表、草稿或迟到结果，昵称/状态更新不销毁正在编辑的 iframe。
- **空状态与离线**：空目录、身份待确认、加载失败、全部离线、全部无连接、协议不受支持分别可辨。离线账号能读写已保存数据；在线查询不可用时保留原数据。显式错误或已移除账号不会自动改为另一个账号。
- **管理动作边界**：不存在页面、账号不完整、未知协议、目录外账号、账号页缺 bot、全局页带 bot、带 bot 不带 page_id 均在 HTTP 边界拒绝且不投递。构造嵌套 `payload.bot` 不会覆盖事件同级 `bot`；伪造全局页或省略页面后调用账号级动作，由插件拒绝缺失账号。
- **数据归属与写入**：在 A 的动作里提交 B 的记录 ID、subject 或批量条目均被拒绝，B 不被读取或修改；A、B 同时保存各自条目后两边数据和全局设置均保留。不再通过过滤后的整份 settings 清空其他账号。
- **服务来源**：账号管理动作及其 detach 后的 `plugin.call` 保持 `management` / `management.ui` 并携带同一 `origin.bot`；服务提供者拒绝与其冲突的 subject 或资源。全局调用不凭空携带账号，聊天和调度来源保持原行为，米游社账号列表不泄漏其他账号记录。
- **目录移除与旧数据**：只能移除无连接账号；移除后其深链失效但全局历史入口仍能查看、清理原记录，同账号重新登录后原归属恢复。缺少账号、完整账号但目录外、QQ 官方不可跨账号迁移三种情况分别处理；空目录仍能打开维护入口。
- **通知与分页**：列表顺序稳定、空列表形状正确、筛选与翻页无静默截断；只发 `events.received` 的既定载荷。变更通知、断线重连和页面恢复后回拉正式结果；当前账号因状态排序移位不会被自动切换。
- **兼容与恢复**：省略 scope 的页面、旧动作格式和全局 settings 行为保持兼容，使用新字段的插件最低版本与首个支持版本一致。当前数据库与旧备份能前向迁移；新备份恢复保留目录及插件数据，在线状态重新确认。相关 fixtures、HTTP 示例、生成物和文档齐备。

## 暂不包含

- 机器人换号迁移：使用者声明“账号 A 已更换为 B”后批量改写保存的地址。只考虑 OneBot11，待本计划落地后再评估；本次目录移除或旧记录归属不承担该功能。
- 按目标记录最近一次实际投递（时间、经由连接、成功与否）：属于各插件的显示改进，在插件计划中安排。
- 把账号页作为管理员权限隔离、改变现有多实例投递选择规则、向插件广播完整历史账号目录。
